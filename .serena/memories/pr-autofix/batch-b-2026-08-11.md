## Tooling defects discovered (not fixed, out of scope for this batch - flag for maintenance)

1. `pr_autofix_lease.py`'s JSON never populates `Data.held_by` on a SKIP verdict; SKILL.md's own snippet (`jq -r '.Data.held_by // "unknown"'`) always reads "unknown". The real owner is in `Data.reason` as `held-by:<owner>` - usable, but SKILL.md documents the wrong field name.
2. `invoke_push_pr_script_identity_guard.py` (PreToolUse hook, issue #4764) denies SKILL.md's own canonical `python3 "$SCRIPTS_DIR/script.py" ...` invocation shape for at least `pr_autofix_lease.py status` (scope criterion B: script operand carries shell expansion, so the guard can't prove it isn't `new_pr.py`) - but allowed the identical shape when wrapped in `LEASE=$(...)` command substitution during an `acquire` call. SKILL.md's bash snippets will trip this hook verbatim in this environment; the workaround used throughout this session was switching to a literal, non-variable script path per call.
3. Lease renewal is mutation-triggered only (`run_pr_mutation_if_live` renews before a mutation), not time-triggered. A long read-only phase (test runs, code investigation, no push) between mutations lets the 15-min TTL lapse even though the agent never stopped working. This caused the #4869 lease loss above. A true background timer-based renewal (as SKILL.md's bash `start_lease_renewal` daemon describes) would close this, but is hard to sustain across separate tool-call boundaries in some harnesses - worth explicit design attention.
4. `get_pr_checks.py`, `why_pr_blocked.py`, `test_pr_merge_ready.py` can report a false-green (`CanMerge: true`, 0 failing required) while GitHub's own `mergeStateStatus` is `BLOCKED`, when a required check context has two runs on the same SHA from different trigger events (pull_request vs push) and the later one failed. See #4721 note above for repro. This is the most safety-relevant finding of the session: a session that trusted `CanMerge` alone (rather than cross-checking `mergeStateStatus` directly, as the Ready-to-Merge Definition already mandates) could have attempted a merge GitHub would then correctly reject - not a silent bad merge on this branch-protected repo, but would be on a repo/permission level that allows override.

## Process note for future batches

Checking `pr_autofix_lease.py status --pull-request N` (no side effects) before delegating an implementer avoided at least 2 wasted delegations once the pattern of sibling contention became clear after the first (#4721) SKIP. Recommend this as standard practice: poll lease status for the whole queue up front, only delegate to PRs currently free, and re-poll periodically for ones that were held.
