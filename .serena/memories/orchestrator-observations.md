# Skill Sidecar Learnings: Orchestrator

**Last Updated**: 2026-10-19
**Sessions Analyzed**: 3

## Observations (MED confidence)

- Subagents correctly refuse owner approvals relayed by the orchestrator. Evidence: decision D5 for PR #5992 `--approve-untrusted-config`. The orchestrator runs owner-gated commands itself and records the approval on the PR. (Session claude-session-0191QTCyqXgwVXfiZgDSfTcn, 2026-09-29)
- A user message sent mid-turn reached about 20 running workflow subagents, and each acted on it alone. The user asked for a label on human-blocked issues. The orchestrator created `blocked:owner-action`, and a subagent created `blocked:human`. A later audit removed 13 of 38 agent-applied labels as wrong. When a relayed request mutates shared state (labels, settings, issue bodies), one owner should act and the rest should report. (42-issue sweep, 2026-10-18) Follow-up 2026-10-19: the audit file `wave2.json` records 12 removals (keep=false) of 38, so the 13th has no file record. Every removal reason says the item's next step was agent work ("Normal fix PR"). No written test defined owner-only action, so each agent judged alone. The labels were consolidated on `blocked:human`. Policy denied `gh label delete`, so an empty `blocked:owner-action` label remains. Retro: `.project-toolkit/retrospective/2026-10-19-issue-sweep-round2.md`.
- Out-of-credit reviewers fail every call, not some. The Codex workspace ran out early in the triage run, and all later GPT 5.6 Sol calls failed with "Your workspace is out of credits". That covered 26 of 42 triage checks and every PR review. Cursor's route to the same model hit a weekly usage cap. A one-call probe before launch shows the model responds, not that it has quota for the run. (42-issue sweep, 2026-10-17) Recurrence: 12 of the 26 triage failures cite "out of credits" in `triage.json`. In wave 2, Sol completed 8 of 76 review rounds; all 68 others cite "out of credits" and fell back to Opus. Round 2 on 2026-10-19 ran the Sol audit on 0 of 45 PRs and Sol triage on 1 of 19 issues. The same round lost 24 fix agents to the Claude weekly limit. Credit can run out between waves, so a launch probe covers one wave at most.
- Eureka, review convergence: more adversarial rounds did not converge an open-ended reviewer, but a frozen contract did. Six PRs went through 5 unbounded rounds each and still had 1 to 4 blocker or major findings, because every round raised new scope. One bounded round on the same six PRs counted only defects the diff introduced plus unmet acceptance criteria, and listed everything else as flagged notes. It found 0 counted findings on four PRs and 1 real defect on two (#6676 and #6681, a fail-open in `tests/hooks/managed_image_marker_parsers.py`). The usual advice is to review again until clean. The evidence says to freeze what counts as a finding first. (42-issue sweep, PRs #6676 #6681 #6686 #6687 #6690 and ubuntu-machine-config #220, 2026-10-18) Outcome: issue #6745 filed the frozen finding contract, and PR #6750 landed it in the review skill (merge `62bcbe976d`, 2026-10-19). The 3-round cap had not stopped the loop: the user asked to repeat until no new issues, and wave 2 alone ran 76 rounds on 19 PRs.
- Eureka, pre-written amendments: ADR-083's Review Date section pre-wrote the amendment it expected ("the tag plus the dogfood install were the durable outcome"). The tag never shipped. A date bump that copied that sentence would have recorded a false fact. The 2026-10-18 review re-measured the criteria instead and recorded what the evidence showed (issue #6742). When a review date section holds a ready-made outcome, treat it as a hypothesis and re-measure before copying it. (42-issue sweep, ADR-083 review, 2026-10-18)
- A decision option was offered without running the gate it would change. To clear the red `Run Python Tests` check from ADR-083 (#6742), option A proposed adding ADR-083 to `scripts/validation/adr_lifecycle_baseline.json`, sized as minutes of work. `check_adr_lifecycle.py` refuses that edit ("The baseline may only shrink"), and the baseline file's own description says "never added or raised". The owner then answered a second decision (D2) and four ADR questions. One run of the check, or one read of the file header, would have removed option A. Retro class: 9, Confident-Incorrectness. (42-issue sweep, 2026-10-18)
- Security review of verifier hunks before the owner ask gave the owner evidence to approve on. Four PRs changed scripts the completion gate runs (#6694, #6695, #6701, #6716). An independent review of only those hunks returned APPROVE_WITH_NOTES on all four, with `can_weaken_gate: false` and 8 to 11 notes each (`secreview.json`). The owner approved all four, and all four merged. (42-issue sweep, 2026-10-18)
