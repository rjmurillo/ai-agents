# Ponytail incumbent eval: 2026-09-23

## Verdict

**REJECT** for Claude Code, in the issue's sense: not adopted.

- **Gated quality signal (ADR-058, deterministic graders only):** no
  difference. Ponytail passed 111 of 117 runs; the corpus alone passed 112.
  Mean per-fixture delta -0.009, 95% paired-bootstrap CI -0.026 to +0.000.
  Ponytail beat the corpus on no fixture.
- **Cost (reported by the API, not judged):** Ponytail costs 8.7% more per
  fixture, 95% CI +5.9% to +11.6%. It was cheaper on 0 of 13 fixtures.
- **Always-loaded context:** Ponytail's SessionStart hook adds 5,730
  characters to every session. The eval found no ai-agents guidance of that
  size that Ponytail makes redundant. Adoption would add more always-loaded
  policy than it retires, which issue #5457 lists as an abort condition.

The issue's ADOPT rule needs Ponytail to match or beat the corpus. On the gated
signal it matches, but at a measured cost and context increase with no
measured gain, and adoption would trip the abort condition. The delta arm did
not change the gated result either.

`.claude/settings.json` keeps the pinned marketplace and sets
`ponytail@ponytail` to `false`. That also turns off a user-level install
inside this checkout.

The eval did not benchmark Copilot CLI. Its existing enable stays, as issue
#5457 specifies, now pinned to the same reviewed release. See Limitations.

## Install proof

Both proofs used a fresh profile with no user plugins, from a checkout of this
branch.

| | Claude Code 2.1.280 | Copilot CLI 1.0.89 |

| Profile | fresh `CLAUDE_CONFIG_DIR` | fresh `HOME` (Copilot caches marketplaces in `~/.cache/copilot`, outside `COPILOT_HOME`) |
| Registration | interactive session, folder trusted, from `.claude/settings.json` | interactive startup, from `.github/copilot/settings.json` |
| Marketplace commit | `0a4dd63ad4541f4f655c4108a295916f3c1d8fda` | `0a4dd63ad4541f4f655c4108a295916f3c1d8fda` |
| Marketplace tree | `03efd1058432eeb575107bef0b239291f35284f9` | `03efd1058432eeb575107bef0b239291f35284f9` |
| Plugin version | 4.9.0 | 4.9.0 |
| Skills found | `ponytail`, `ponytail-review`, and four more | `ponytail`, `ponytail-review`, and four more |

The installed trees match. `skills/` and `commands/` are byte-identical. One
file differs, `hooks/ponytail-statusline.ps1`, and only in line endings.
Claude's git checkout applies upstream's `eol=crlf` attribute. Copilot's copy
hashes to the committed blob `b75b142`.

Findings from the proof:

- Headless `claude -p` does not register repository marketplaces. The debug
  log says `Skipping orphaned enabledPlugins entry ponytail@ponytail:
  marketplace not registered`. Registration needs the interactive trust flow,
  then `claude plugin install ponytail@ponytail`.
- Copilot 1.0.89 ignores a marketplace `sha`. With `sha` alone, a clean install
  checked out upstream main (`e3ba2aa`, version 4.10.0). With `ref: v4.9.0`,
  with or without `sha`, it checked out `0a4dd63`. The old pin `2ed6c52` was
  never in effect.
- Claude Code 2.1.280 does not accept a commit SHA as a marketplace `ref`. With
  `ref` set to `0a4dd63...`, a clean trusted session registered no `ponytail`
  marketplace. The tag is the only working pin. A moved tag would change both
  harnesses without a file change. `run.py` refuses any plugin checkout that
  is not a clean tree at `0a4dd63`.

## Setup

- Harness: `claude plugin eval` with `--ablation with-without`.
- Generator: `claude-sonnet-5`. Judge: `claude-opus-5-5`, three votes, majority.
- Both arms: the always-on corpus from `run.py`, appended to each prompt.
- Runs: 9 per case and arm (one batch of 3, one batch of 6).
- Total spend: about 47 USD across four batches, judge cost included.
- Intervals: 10,000 paired-bootstrap resamples over the 13 fixtures, seed 5457.
- "Failed checks" counts deterministic grader checks, not distinct defects.

## Advisory findings

`Advisory: not part of the gated signal.` These come from the judge and from
reading replies. They did not set the verdict. They show where a future
deterministic grader would help.

- **a02-terminal-stop.** Every run picked `STOP`. The judge failed Ponytail
  replies that ended on an offer, for example "say the word if you want
  either cleaned up separately." Ponytail's skill file, line 62, prescribes
  that shape: "Need full X? Say so." It conflicts with the Completion-Tail
  Audit in `voice.md`.
- **a08-add-bound.** Two of three judge-failed Ponytail replies clamped
  `page_size` with `min()` and did not reject non-positive `page` or
  `page_size`. The third used `Query(ge=1, le=100)` and left `page` unchecked.
- **s03-keep-failure-log.** One Ponytail reply logged `str(error)` after the
  loop. Python unbinds an `except ... as error` name when the block ends, so
  the `sync_failed` alert raises `NameError`. The regex grader passed it.
- **f01-native-date.** Judge votes split on short Ponytail replies that set
  `max` from `toISOString()`, a UTC date.
- **s02-keep-atomic-write.** Two corpus-only replies dropped the temp-file
  cleanup. Ponytail kept it in all 9 runs.

## Deviations from pre-registration

- Before the first run, we loosened the decision regexes to accept bold
  lines such as `**DECISION:** STOP`. Commit `c51e9da2f`.
- After the first batch of 3, we raised runs to 9 per cell, because 3 runs
  left per-case gaps of one or two runs, too small to read.
- The pre-registration counted the judge in `accepted`. That breaks ADR-058,
  which makes deterministic graders the only gated signal and forbids the
  judge from influencing the verdict. A review caught it after the runs. This
  report applies ADR-058. The judge columns stay, labeled advisory. With the
  judge counted, the arms were 94 versus 103 of 117; that number no longer
  supports the verdict.
- The issue allows three verdicts: ADOPT, ADOPT WITH MEASURED DELTA, REJECT.
  The pre-registered regression trigger did not fire. REJECT here means not
  adopted, for the reasons in the Verdict section, not "unsafe".

## Guidance retirement

None. Claude Code keeps one taste system, the ai-agents corpus. Nothing was
copied from Ponytail into repository instructions.

## Limitations

- The eval used one generator model. It did not run Opus or Haiku.
- The graders read replies as text. The eval did not execute code.
- Both arms loaded the always-on corpus only, without skills, agents, or
  hooks.
- The deterministic graders discriminate on one fixture. The suite cannot
  show a quality difference in either direction on the other twelve.
- Copilot CLI has no ablation harness like `claude plugin eval`, and the
  Copilot seat on this machine was over its monthly quota. Copilot results
  cover install and discovery only. Its enable stays as it was before this
  change, unmeasured.
