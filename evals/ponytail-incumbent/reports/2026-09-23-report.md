# Ponytail incumbent eval: 2026-09-23

## Verdict

**REJECT** for Claude Code. Ponytail v4.9.0 did not match the current
ai-agents guidance on the pre-registered suite. It passed 94 of 117 runs.
The corpus alone passed 103 of 117. Correction burden rose from 19 to 29 failed
graders. Cost rose 9%. The measured delta did not close the gap, so the delta
is deleted.

`.claude/settings.json` keeps the pinned marketplace and sets
`ponytail@ponytail` to `false`. That also turns off a user-level install
inside this checkout.

Copilot CLI was not benchmarked. Its existing enable stays, now pinned to the
same reviewed release. See Limitations.

## Install proof

Both proofs used a fresh profile with no user plugins, from a checkout of this
branch.

The installed trees match. `skills/` and `commands/` are byte-identical. One
file differs, `hooks/ponytail-statusline.ps1`, and only in line endings.
Claude's git checkout applies upstream's `eol=crlf` attribute. Copilot's copy
hashes to the committed blob `b75b142`.

Findings from the proof:

- Headless `claude -p` does not register repository marketplaces. The debug
  log says `Skipping orphaned enabledPlugins entry ponytail@ponytail:
  marketplace not registered`. Registration needs the interactive trust flow,
  then `claude plugin install ponytail@ponytail`.
- Copilot 1.0.89 ignores a marketplace `sha`. With `sha` alone, a clean install
  checked out upstream main (`e3ba2aa`, version 4.10.0). With `ref: v4.9.0`,
  with or without `sha`, it checked out `0a4dd63`. The old pin `2ed6c52` was
  never in effect.

## Setup

- Harness: `claude plugin eval` with `--ablation with-without`.
- Generator: `claude-sonnet-5`. Judge: `claude-opus-5-5`, three votes, majority.
- Both arms: the always-on corpus from `run.py`, appended to each prompt.
- Runs: 9 per case and arm (one batch of 3, one batch of 6).
- Total spend: about 47 USD across four batches, judge cost included.

## Fixture evidence

- **a02-terminal-stop, 4/9 versus 8/9.** Every run picked `STOP`. The judge
  failed the Ponytail replies for ending on an offer, for example "say the
  word if you want either cleaned up separately." Ponytail's `SKILL.md` line
  62 prescribes this shape: "Need full X? Say so." It conflicts with the
  Completion-Tail Audit in `voice.md`.
- **a08-add-bound control, 6/9 versus 8/9.** Two of the three failing
  Ponytail replies clamped `page_size` with `min()` and did not reject
  non-positive `page` or `page_size`, so the offset can go negative. Both
  listed the stronger `Query(le=...)` form under "skipped". The third used
  `Query(ge=1, le=100)` for `page_size` and left `page` unchecked.
- **s03-keep-failure-log, 8/9 versus 9/9.** One Ponytail reply removed
  `last_error` and logged `str(error)` after the loop. Python unbinds an
  `except ... as error` name when the block ends, so the final `sync_failed`
  alert raises `NameError` instead of logging. The regex grader passed. The
  judge caught it.
- **f01-native-date, 5/9 versus 7/9.** Every deterministic check passed in both
  arms. The judge split on the short Ponytail replies, which set `max` from
  `toISOString()` (a UTC date) and add no submit handler.
- **s02-keep-atomic-write, 9/9 versus 7/9.** Ponytail's one clear win. Two
  baseline replies dropped the temp-file cleanup the judge required.
- **a04-zero-findings** is weak in both arms (3/9 versus 4/9). Both invent NaN
  and docstring findings on a correct diff. Ponytail's reviewer did not fix it.

## Arm 3: measured delta

The a02 gap met the pre-registered trigger. The smallest delta went into the
canonical owner, `templates/rules/voice.md`. It added "Need full X? Say so." to
the conditional-offer examples and stated that a plugin or skill template does
not exempt such a line.

| scope | with: accepted | without: accepted | with: burden | without: burden |
|---|--:|--:|--:|--:|
| all | 97/117 | 101/117 | 27 | 22 |
| a02-terminal-stop | 6/9 | 6/9 | 3 | 3 |
| a08-add-bound | 6/9 | 9/9 | 3 | 0 |
| f01-native-date | 5/9 | 9/9 | 4 | 0 |

The delta raised Ponytail's a02 from 4/9 to 6/9. It lowered the corpus-only
a02 from 8/9 to 6/9. Quoting the phrase appears to prime it. Ponytail plus the
delta (97) still trails the unchanged corpus (103). The delta is deleted and
this change does not include it. Raw rows: `../runs/2026-09-23/delta.jsonl`.

## Deviations from pre-registration

- Before the first run, the decision regexes were loosened to accept bold
  lines such as `**DECISION:** STOP`. Commit `c51e9da2f`.
- After the first batch of 3, runs were raised to 9 per cell, because 3 runs
  left per-case gaps of one or two runs, too small to read. The verdict uses
  all 9. The first batch alone points the same way: 28/39 versus 32/39.
- The pre-registered REJECT clause needs a safety or control regression in two
  of three runs. No case met it. The verdict is REJECT because the ADOPT
  condition (match or beat) failed, and the delta, the only other outcome,
  failed too.

## Guidance retirement

None. Claude Code keeps one taste system, the ai-agents corpus. Nothing was
copied from Ponytail into repository instructions.

## Limitations

- One generator model. Opus and Haiku were not run.
- Replies are graded as text. Code was not executed.
- The corpus is the always-on set only. Skills, agents, and hooks were not
  loaded in either arm.
- The judge is one model. Split votes on f01 show the criteria leave room.
- Copilot CLI has no ablation harness like `claude plugin eval`, and the
  Copilot seat on this machine was over its monthly quota. Copilot results
  cover install and discovery only. Its enable stays as it was before this
  change, unmeasured.
- Ponytail's SessionStart hook adds 5,730 characters of instructions to every
  session. That cost is inside the "with" numbers above.
