# skill-bootstrap Scripts

The detail behind the Scripts section of `SKILL.md`.

Each CLI uses only the Python standard library, prints JSON (with an `examined` count, except `bootstrap_adr.py draft`), writes nothing inside the repository (`bootstrap_eval.py freeze` writes there only with `--allow-in-repo`; `bootstrap_adr.py draft` only creates a new file in a located ADR folder; `bootstrap_mine.py --out` refuses an in-repo path with no override), and runs on Linux, macOS, and Windows.

`bootstrap_friction.py`, `bootstrap_review.py`, and `review_clusters.py` are modules the miner imports, not CLIs. `replies_corpus.py`, `replies_flags.py`, `replies_prepare.py`, `replies_sample.py`, and `replies_tally.py` are modules `replies_audit.py` imports. `boundary_grants.py` is a module `bootstrap_boundary.py` imports to parse and check its grants. `adr_shape.py`, `adr_commits.py`, and `adr_reason.py` are pure-function modules for ADR detection, ported from align-cli under MIT (`LICENSE-align`); they have no CLI and do no I/O. `adr_shape.py` also holds the trailer and importer-text cleaning, and `adr_commits.py` also holds the text helpers and the pull request selection. `adr_docs.py`, `adr_log.py`, `adr_locate.py`, `adr_scan.py`, `adr_write.py`, and `bootstrap_adr.py` are the I/O side: `adr_docs.py` classifies README, changelog, and contributing rules and holds what existing ADRs name, `adr_log.py` reads decision-log and ledger files, `adr_locate.py` finds the ADR folders and renders drafts, `adr_scan.py` runs git and lists the candidates, and `adr_write.py` holds the checks on where a file may go and the create-only write. `adr_write.py` is not a port: align-cli has no write boundary. `adr_scan.py` reads commits with `git rev-list` and `git cat-file --batch`, with replacement objects off, so a commit message or a `git replace` cannot forge a record. `bootstrap_adr.py` is the only CLI of the group and also holds the ADR drafting code.

Exit code 0 means success and exit code 1 means findings that need action, for every script. Exit codes 2 and 3 differ by script:

| Script | Exit 2: configuration | Exit 3: external |
|---|---|---|
| `bootstrap_mine.py` | Bad arguments; not a repository; bad rev; unreadable `TARGET` or `--prs-json`; refused `--out`; an authored file over the 5 MiB read cap | Git missing, failed, or timed out; a working-tree read failed; `--out` write failed, including a write race |
| `bootstrap_forms.py` | Bad arguments; unreadable or malformed plan | None |
| `bootstrap_eval.py` | Bad arguments; unreadable or malformed cases, results, or frozen file; edited frozen file; refused `--out`, including a write race | Git missing, failed, or timed out; the regex grader child failed; `--out` write failed; any other I/O error |
| `bootstrap_sweep.py` | Bad arguments; malformed or mismatched input; run directory in the repository or not empty; changed judge rubric; git missing or failed; any read or write failure (payload `error` is `io`) | None |
| `replies_audit.py` | Bad arguments or pattern; a store that is missing or is a store root; a run directory that exists or sits in the repository or a store; an empty population; a missing marker match; an unreadable or mismatched run directory or label file (payload `error` is `config`) | Other read or write failure |
| `bootstrap_drift.py` | Bad arguments; repo or skills root not a directory; unknown `--name` | None; an unreadable `reverify.json` is `malformed` (exit 1) |
| `bootstrap_boundary.py` | See the detail below | Git missing, failed, or timed out; an unreadable working-tree file |
| `bootstrap_adr.py` | Bad arguments, printed as JSON like every other error, including `--max-commits` above 10,000; a partial clone (`extensions.partialClone`, a promisor remote, or a partial clone filter) when git predates `GIT_NO_LAZY_FETCH` (2.45.1, or 2.39.4, 2.40.2, 2.41.1, 2.42.2, 2.43.4, 2.44.1 on those lines), because it may fetch a missing commit; not a repository; bad rev, `--since`, or `--prs-json`; a `--scan` or `--prs-json` path that is not a regular file; a `--prs-json` file over 16 MiB, or a `--scan` file or a scan report over 128 MiB; a `--scan` or `--prs-json` file that cannot be opened or read (payload `error` is `config`), is malformed, or is not valid UTF-8; on git before 2.36, a scan from a linked work tree whose main work tree cannot be found (its git dir was made with `--separate-git-dir`); a `--repo` folder that the work tree git names (through `core.worktree`) does not contain; `draft` into a folder whose highest ADR number is 999999, the last one the locator reads; a refused `scan --out` (inside any work tree of the repository, a directory, or already there); a `draft --out` that exists and is not a directory, or that is inside a work tree and is not a located ADR folder of it or is ignored by git (a folder that no work tree encloses, where git says "not a git repository", is a scratch folder and takes the draft; any other git failure there is an error, and a dubious-ownership refusal is exit 3); a draft over 1 MiB, the most a scan reads back from an ADR; a candidate title that is empty once control characters are removed; a `--status` other than Proposed, Rejected, Deprecated, or Superseded (a draft is never Accepted, per the ADR lifecycle rule that acceptance needs review); JSON nested past the recursion limit or text that cannot be written as UTF-8; any other read or write failure (payload `error` is `io`); an unexpected exception (payload `error` is `internal`) | Git missing, failed, timed out, could not be started, or refused a repository for dubious ownership |

The payload `error` names the cause: `config` for exit 2, and `git` or `io` for exit 3. `bootstrap_mine.py`, `bootstrap_boundary.py` and `bootstrap_eval.py` report `io` with exit 3 for read and write failures; `bootstrap_adr.py` reports only `git` with exit 3. `bootstrap_sweep.py` and `bootstrap_adr.py` report `io` with exit 2 for read and write failures, except that `bootstrap_adr.py` reports `config` when it cannot open or read its `--scan` or `--prs-json` input. `bootstrap_sweep.py` also reports git failures as `config` with exit 2. `bootstrap_adr.py` also exits 2 with `internal` for an unexpected exception, because its exit 1 is reserved for `exists` and exits 3 and 4 mean external and auth.

`adr_corpus_truncated` when reading existing ADRs, newest first, stopped at 2,000 files or at the first ADR whose text would take the total past 32 Mi (33,554,432) characters; drop counts per filter, with `pr_incomplete` for export rows that are not merged, miss a field (the `body` key included), have a `body` that is not a string or null, have no `author` (or `user`) object with a nonblank string `login`, have a merge time with text after the date, or have a URL whose path does not end in the row's own number (as `/pull/<number>` when a path segment is `pull`), `pr_duplicate` for a later row of a number already kept (the first row wins), `pr_other_repo` for export rows whose URL is not `<origin>/pull/<number>` by host, port (443 is the default), and path, without regard to case (a GitLab origin matches none, because its URLs are not `/pull/`, and neither does an origin that is not on GitHub or GitLab; the origin is the URL `git remote get-url origin` gives, with `insteadOf` applied; with no origin nothing is dropped), `commit_too_large` for a commit object over 1 MiB, and `log_over_limit` for decision-log candidates past 1,000 per file and entries past 5,000 per file; a pull request candidate that takes its reason from a commit it covers names that commit in `source.reason_sha` and `source.reason_url` (null with no GitHub or GitLab origin), and its draft cites it next to the reason; a decision-log candidate id is `log-` plus `source.entry_id`, which is `<id>--` and 8 hex digits of the SHA-256 of the entry's full title (the candidate `title` shows the first 120 characters), with `-<n>` added when a key is already taken or is another entry's literal id, so same-title twins differ only by order. Ids compare without regard to case. An entry is documented when an ADR names its key. Its key without literal-id reservation, or its bare id, documents it only while that word names no other entry in the logs read; when a second entry later takes an id that an ADR names only bare, or a literal id equals another entry's unreserved key, both entries are proposed again, because the ADR cannot tell them apart |
| `bootstrap_adr.py draft` | 6 | One new ADR, status `Proposed` by default (`--status` sets Rejected, Deprecated, or Superseded, and the payload reports it), published create-only, so neither path replaces a file. A complete temporary file hard-linked into place publishes atomically. Where the file system has no hard links, the file is created with mode `x` and written in place, so a reader can see it empty or partial |

`bootstrap_boundary.py` detail: `plan` exits 1 on a conflict or an invalid name. `verify` exits 1 on a path outside the boundary, an existing skill changed without `--update`, an ignored file written in a skill (it would not ship), a path under an `--also-create` grant that changed in any way other than a new untracked file (`create-only-changed`; a path the snapshot HEAD tracks, a new symlink or nested repository, and a new `.gitignore` or `.gitattributes` in any letter case never count as new; an ignored `.gitignore` or `.gitattributes` under the grant also fails, even one that predates the run; a path an `--also-allow` grant also covers follows `--also-allow`), HEAD or branch moved, or index flags or `info/exclude` changed. Exit code 2 covers bad arguments; an output root outside the allowed set; an output root, skill directory, `--also-allow` path, or `--also-create` path that git ignores; an `--also-allow` or `--also-create` path outside the repository, under `.git`, or overlapping a skills root; a symlink in any of those paths; or a snapshot that already exists, is inside the repository, is unreadable, or is from another repository or output root. `verify` does not see gitignored files outside the output root, including other ignored files inside an `--also-create` grant, empty directories, other writes inside `.git/`, or tag, config, and push operations. It catches accidental writes by a cooperating run; it is not a sandbox. Only the Phase 1 snapshot counts, so `snapshot` refuses to overwrite an existing file. An unreadable file in the working tree stops `snapshot` with exit code 3 before any write.

`bootstrap_drift.py` runs a `command` check only with `--allow-commands`; review the argv first, because it executes repository code. The command gets no stdin, discarded output, and only `PATH`, `HOME`, `LANG`, `LC_ALL`, `SYSTEMROOT`, `TEMP`, and `TMP` from the environment, each only when set. Never pass `--allow-commands` in a job that holds secrets or runs on untrusted pull request content.

`bootstrap_adr.py` exits 1 only when `draft` finds its target file already there, or finds another ADR with the same number after it wrote (payload `error` is `exists`, with `written: false` in the first case and `written: true` in the second). In the second case it leaves the draft on disk: `path` names it, `others` names the other ADRs, and the caller must renumber or remove one of the two. It never retries with another number.

`scan` and `draft` check `--out` by path and then write by path. The `--out` folder and its parents must not change during a run: a local process that can write an ancestor folder and swaps it after the check can move the write elsewhere. The write stays create-only and runs with the caller's own rights. When a published file's temporary copy cannot be removed, a `scan` or `draft` that otherwise succeeds still exits 0, and its payload names that copy in `leftover`; an `exists` payload does not name it.

`bootstrap_adr.py scan` reads git and the working tree and makes no network call. `--out` must be outside every work tree of the repository, linked ones included. `--since` must be an ISO 8601 date such as `2026-01-31`, or a date and time such as `2026-01-31T08:00:00Z`; a bare date means local midnight, and compact or week dates are refused because git misreads them. `--since` needs git 2.37 or later, because the scan passes `--since-as-filter`, so a commit behind an older child is still read. `--prs-json` is a JSON list of merged pull requests. Each item needs `number`, `title`, `body` (a string or null, never omitted), `url` (or `html_url`, an https page whose path ends in the number, as `/pull/<number>` when a path segment is `pull`), `merged_at` (or `mergedAt`, a bare `YYYY-MM-DD` or a full ISO 8601 timestamp with `T` between date and time), and `author` (or `user`), an object with a nonblank string `login`. `merge_commit_sha` (or `mergeCommit.oid`) is optional.

`bootstrap_adr.py` finds ADR folders in three steps. It reads an `.adr-dir` file and checks the known folder names together. Only when those find nothing does it look for any folder with three or more ADR-named files. Inside the repository, `draft` writes only into a folder found this way, and a folder with no ADR-named file is not one. It refuses a path that git ignores. An `rfc` or `rfcs` folder, or a folder reached through a symlink with that name, is read, so its links still hide decisions, but it has `draft_target: false`. It is never `primary`, and `draft` refuses it. A draft title drops the commit's `type(scope)!:` prefix and its trailing `(#N)`.

## Windows PowerShell

On Windows PowerShell 7, set the plugin root once, then run the same subcommands with `python`. This form takes the first non-empty value of `COPILOT_PLUGIN_ROOT`, `CLAUDE_PLUGIN_ROOT`, and `.claude`, and does not use the locator check the bash form uses (ADR-121 decision 1 leaves PowerShell to a follow-up):

```powershell
$root = @($env:COPILOT_PLUGIN_ROOT, $env:CLAUDE_PLUGIN_ROOT, '.claude') | Where-Object { $_ } | Select-Object -First 1
python "$root/skills/skill-bootstrap/scripts/bootstrap_boundary.py" snapshot --repo . --output-root <output-root> --out "<snapshot path>"
```
