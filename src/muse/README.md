# Muse platform tree

The project-toolkit skills and agents rendered for the Muse Code CLI
(<https://dev.meta.ai/docs/muse-code>). This tree is generated by the
standard build from `templates/platforms/muse.yaml`; do not hand-edit
anything under `skills/`, `agents/`, or `lib/`. The sources are `src/claude/skills/` and the
shared packages under `scripts/`. Regenerate with:

```bash
uv run python build/scripts/build_all.py
```

## Layout

- `skills/<name>/SKILL.md`: one directory per skill. The frontmatter
  keeps only `name` and `description`, the two fields Muse custom
  skills consume; bodies ship verbatim from the Claude sources.
- `agents/<name>.md`: one Markdown file per agent. The frontmatter
  keeps only `name` and `description`, because Muse Code cannot spawn an
  agent with an unrecognized key. An agent whose Claude file declares a
  `tools` list is not shipped, and each shipped body names the agents left
  out. `model` and `disallowedTools` are dropped.
- `lib/`: the shared Python packages the skill scripts resolve
  against, rendered from `scripts/` by `lib_mirror.py`, mirroring the
  `src/claude` layout.

Meta documents no plugin manifest for Muse Code, and there is no install
size cap, so the tree is flat where Hermes needs packs. The Hermes pack exclusions do not
apply here: every one is a Hermes `plugin_guard` verdict (ADR-115
Decision 6), and Muse has no equivalent guard. This tree therefore
ships the same skill set as `src/codex` (ADR-115 Decision 2).

## Install into Muse

Muse loads custom skills from `~/workspace/custom-skills/`. Skill scripts
resolve the shared packages from `lib/` one level above that directory, at
`~/workspace/lib/`. Copy both from the repository root. Without `lib/`, any
script that imports a shared package exits with `Plugin lib directory not
found`.

The skills and `lib/` are one release. Old scripts run against new packages
(or the reverse) can fail on a missing module, so the install replaces both.
Any skill directory or `lib/` already present is moved, not deleted, to
`~/workspace/muse-install-backup-<timestamp>/`. That includes a skill of your
own that uses the same name as a shipped skill, and a `lib/` with files the new
release dropped:

```bash
backup=~/workspace/muse-install-backup-"$(date +%Y%m%d%H%M%S)"
mkdir -p ~/workspace/custom-skills
if [ -e ~/workspace/lib ]; then
  mkdir -p "$backup"
  mv ~/workspace/lib "$backup"/lib
fi
cp -R src/muse/lib ~/workspace/lib
for d in src/muse/skills/*/; do
  name="$(basename "$d")"
  if [ -e ~/workspace/custom-skills/"$name" ]; then
    mkdir -p "$backup"/custom-skills
    mv ~/workspace/custom-skills/"$name" "$backup"/custom-skills/"$name"
  fi
  cp -R "$d" ~/workspace/custom-skills/"$name"
done
```

Check the install by running one skill script:

```bash
python3 -I ~/workspace/custom-skills/github/scripts/pr/get_pr_checks.py --help
```

The skills path `~/workspace/custom-skills/` above comes from no official
page. Muse Code documents `~/.agents/skills` (user) and `.agents/skills/` <!-- agents-write-target: historical -- Muse Code's documented read path, not a write target of this repo -->
(project) at <https://dev.meta.ai/docs/muse-code/extending>. The steps above
keep that path. Nobody has measured it against Muse Code.

## Install agents into Muse Code

Muse Code loads user agents from `${XDG_CONFIG_HOME:-$HOME/.config}/muse/agents/`
(<https://dev.meta.ai/docs/muse-code/agents>). Copy the agents from the
repository root. A file already there with the same name is moved, not
deleted, to `~/.config/muse/agents-backup-<timestamp>/`:

```bash
agents_dir="${XDG_CONFIG_HOME:-$HOME/.config}/muse/agents"
backup="$HOME/.config/muse/agents-backup-$(date +%Y%m%d%H%M%S)"
mkdir -p "$agents_dir"
for f in src/muse/agents/*.md; do
  name="$(basename "$f")"
  if [ -e "$agents_dir/$name" ]; then
    mkdir -p "$backup"
    mv "$agents_dir/$name" "$backup/$name"
  fi
  cp "$f" "$agents_dir/$name"
done
```

The project alternative is `.agents/agents/` in a repository. Muse Code <!-- agents-write-target: historical -- Muse Code's documented read path, not a write target of this repo -->
loads it only after the workspace is trusted. `.agents/` also holds Codex <!-- agents-write-target: historical -- Muse Code's documented read path, not a write target of this repo -->
`.agents/skills` and `.agents/plugins`, so a copy there is shared with Codex <!-- agents-write-target: historical -- Muse Code's documented read path, not a write target of this repo -->
paths.

**A Muse Code load of these agents is NOT VERIFIED until the owner's run,
recorded in the pull request.** Muse Code starts when an agent is invalid, but
the lead cannot spawn it. No run without a login shows whether an agent
loads. The test is `tests/e2e/test_muse_agents_load.py`; it needs
`RUN_CLI_E2E=1`, `muse` on `PATH`, and a logged-in Muse Code.
