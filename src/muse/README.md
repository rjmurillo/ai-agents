# Muse platform tree

One tree serves two Muse targets: Meta's personal agent, and the Muse Code
CLI (<https://dev.meta.ai/docs/muse-code>). This tree is generated by the
standard build from `templates/platforms/muse.yaml`; do not hand-edit
anything under `skills/`, `agents/`, or `lib/`. The sources are
`src/claude/skills/`, `src/claude/agents/`, and the shared packages under
`scripts/`. Regenerate with:

```bash
uv run python build/scripts/build_all.py
```

| Target | Gets | Install section |
|---|---|---|
| Muse personal agent | skills and `lib/` | [Install into Muse](#install-into-muse) |
| Muse Code CLI | skills, `lib/`, and agents | [Install on Muse Code](https://github.com/rjmurillo/ai-agents/blob/main/docs/training/install-on-every-host.md#install-on-muse-code) |

## Layout

- `skills/<name>/SKILL.md`: one directory per skill. The frontmatter
  keeps only `name` and `description`, the two fields Muse custom
  skills consume; bodies ship verbatim from the Claude sources.
- `agents/<name>.md`: one Markdown file per agent, for Muse Code only.
  The frontmatter keeps only `name` and `description`, because Muse Code
  cannot spawn an agent with an unrecognized key. An agent whose Claude
  file declares a `tools` list is not shipped, and each shipped body names
  the agents left out. `model` and `disallowedTools` are dropped, and a body
  whose source denies `Agent` gets a short Subagents section that tells the
  model not to start subagents. That is a prompt instruction, not a block.
- `lib/`: the shared Python packages the skill scripts resolve
  against, rendered from `scripts/` by `lib_mirror.py`, mirroring the
  `src/claude` layout.

Muse has no plugin manifest and no install size cap, so the tree is
flat where Hermes needs packs. The Hermes pack exclusions do not
apply here: every one is a Hermes `plugin_guard` verdict (ADR-115
Decision 6), and Muse has no equivalent guard. This tree therefore
ships the same skill set as `src/codex` (ADR-115 Decision 2).

## Install into Muse

Muse means two hosts. This section is for the Muse personal agent. Muse
Code, the `muse` CLI, does not read `~/workspace/custom-skills/`. It reads
`${XDG_CONFIG_HOME:-~/.config}/muse/skills/`, with `lib/` beside it at
`${XDG_CONFIG_HOME:-~/.config}/muse/lib/`. See [Install on Muse
Code](https://github.com/rjmurillo/ai-agents/blob/main/docs/training/install-on-every-host.md#install-on-muse-code).

The personal agent loads custom skills from `~/workspace/custom-skills/`. Skill scripts
resolve the shared packages from `lib/` one level above that directory, at
`~/workspace/lib/`. Copy both from the repository root. Without `lib/`, any
script that imports a shared package exits with `Plugin lib directory not
found`.

The skills and `lib/` are one release. Old scripts run against new packages
(or the reverse) can fail on a missing module, so the install replaces both.
Any skill directory or `lib/` already present is moved, not deleted, to
`~/workspace/muse-install-backup-<timestamp>/`. That includes a skill of your
own that uses the same name as a shipped skill, and a `lib/` with files the new
release dropped:

```bash
backup=~/workspace/muse-install-backup-"$(date +%Y%m%d%H%M%S)"
mkdir -p ~/workspace/custom-skills
if [ -e ~/workspace/lib ]; then
  mkdir -p "$backup"
  mv ~/workspace/lib "$backup"/lib
fi
cp -R src/muse/lib ~/workspace/lib
for d in src/muse/skills/*/; do
  name="$(basename "$d")"
  if [ -e ~/workspace/custom-skills/"$name" ]; then
    mkdir -p "$backup"/custom-skills
    mv ~/workspace/custom-skills/"$name" "$backup"/custom-skills/"$name"
  fi
  cp -R "$d" ~/workspace/custom-skills/"$name"
done
```

Check the install by running one skill script:

```bash
python3 -I ~/workspace/custom-skills/github/scripts/pr/get_pr_checks.py --help
```

Meta publishes no page for the `~/workspace/custom-skills/` path. The owner
supplied it (PRs #7041 and #7297). The personal agent has no documented agent
format, so it gets skills and `lib/` only, and no agent files.
