# TASK-040: Ship the capability frontmatter contract, its validator, and one real conversion

## Objective

Give every behavior-driving artifact one machine-readable way to declare what it
owns and what it depends on, gate the resulting graph, and prove the mechanism
by converting one real duplicated policy to composition. Closes #5396.

## Milestone 1: the decision record (S)

1. Write `.project-toolkit/architecture/ADR-110-capability-ownership-dag.md`. Record the
   `metadata.capability` schema, the four kinds, the projection rule, and the
   three rejected alternatives from DESIGN-029.
2. Record the reconciliation with issue #5384 as coordination, not commitment.
   #5384 has not chosen a format, so the record names no key on its behalf.
3. Record the relationship to ADR-107: the projection equivalence predicate
   stays in `.agents/governance/GENERATOR-FILES.md`, and this record adds only
   the rule that a projection makes no ownership claim.
4. Run the ADR review and commit the debate log next to the record.
5. Commit REQ-031, DESIGN-029, and this task file in the same pull request.

**Exit**: ADR-110 accepted, spec artifacts merged, no validator shipped yet.
Verified by `uv run python scripts/validation/check_adr_links.py` and by the
debate log existing at `.project-toolkit/critique/ADR-110-debate-log.md`.

## Milestone 2: the validator and its fixtures (M)

1. Write `scripts/validation/check_capability_graph.py` with the four functions
   named in DESIGN-029 and a CLI entry point supporting a text report and a
   JSON report.
2. Enforce the six invariants from REQ-031: single owner, resolvable
   dependency, no self dependency, acyclic, no projection ownership, and
   deprecated requires `replaced-by`.
3. Reject an unknown key inside the `capability` block, so the vocabulary
   cannot drift the way `metadata.type` drifted.
4. Write `tests/validation/test_check_capability_graph.py`. Build the seven
   required shapes with `tmp_path`: valid chain, missing dependency, self
   dependency, cycle, duplicate owner, projection mirroring a canonical owner,
   and a consumer carrying a copied block of its dependency. Assert the exit
   code and the specific message for each negative shape.
5. Add the determinism test: render one fixture tree twice and assert byte
   equality.
6. Register the gate in the `_SEQUENCE` table at
   `scripts/validation/pre_pr_sequence.py:248`.
7. Enforce the one copied-policy class that can be proven: a consumer that
   repeats three or more consecutive lines of the owner it declares a
   dependency on.
8. Run the validator against the real trees and paste node and edge counts by
   kind into the pull request body.

**Exit**: gate green on the real trees, every fixture behaving as intended, and
the counts computed by the script rather than written by hand.

## Milestone 3: the real conversion (M)

1. Compose through the partial mechanism the repository already uses, not
   through a pointer to a rule. An agent running under Copilot CLI never loads
   `.claude/rules/`, so replacing prompt text with a citation would thin the
   control. `templates/skills/partials/` and `templates/agents/partials/`
   already carry shared prose, and `{{> name}}` renders it into each consumer.
2. Write the canonical paragraph once per partial tree, two files, because the
   agent and skill renderers read separate partial directories. Pin the two
   byte-identical with a test, so the pair cannot drift.
3. Replace the copied block in each of the 13 authored locations with
   `{{> untrusted-content}}` plus `depends-on: [untrusted-content-handling]`.
4. Declare `owns: [untrusted-content-handling]` on `templates/rules/security.md`
   and have it name the two partials as the prompt-side rendering of the policy
   it owns.
5. Run `uv run python build/scripts/build_all.py` so every projection is
   regenerated by the pipeline rather than by hand.
6. Preserve consumer-specific procedure. The 13 copies are not interchangeable:
   `templates/agents/code-reviewer.shared.md` tells the reviewer to report an
   embedded instruction as its own finding, and
   `templates/skills/research.SKILL.md.tmpl` carries a control-plane carve-out
   that only a tool-heavy skill needs. Diff all 13 before editing any, move the
   shared core to the owner, and keep the role-specific half where it is.
7. Record the before and after authored-location count with the command that
   computes it, not by hand: 13 before; 2 canonical partials plus 4 residual
   copies after. The residue is the four `templates/agents/*.shared.md` bodies.
   `build/generate_agents.py` reads those files directly and runs no mustache
   expansion, so a partial include would leak the literal token into the VS Code
   agent tree. They convert when ADR-109 B1 finishes moving that tree onto the
   per-harness templates; until then the shared body and its partial are two
   authored copies of one agent, which is a pre-existing duplication this
   milestone does not own. The security rule carries the waiver: it names the
   four files, requires them byte-identical to the canonical partial, and says
   a fifth copy is a violation rather than residue.
8. Run the security review axis over the diff, because the converted policy is
   a prompt-injection defense. Compare the rendered output before and after, so
   the diff shows that no consumer lost text at render time.

**Exit**: one canonical owner, every consumer-specific procedure still present,
the gate green, and the security axis clean.

## Milestone 4: retire `metadata.type` (S)

Epic #5456 allows a new validator only when it removes or consolidates an
existing mechanism. This milestone is that removal, and without it ADR-110's
"superseded" claim is unearned.

1. Map each of the nine `metadata.type` values on the 14 skill templates to one
   of the four `capability.kind` values.
2. Replace `metadata.type` with `metadata.capability.kind` in those templates.
3. Regenerate the projections with `build/scripts/build_all.py`.
4. Add `type` to the keys the validator refuses inside the `capability` block,
   so the retired vocabulary cannot return under the new key.
5. Record the before and after value count in the pull request body: nine
   unchecked values before, four checked values after.

**Exit**: no `metadata.type` remains in `templates/skills/`, and the gate is
green.

## Milestone 5: tell agents to compose (S)

The architecture criterion in issue #5396 is that agents are instructed to
compose existing capabilities before copying policy. A decision record does not
reach an agent while it authors. This milestone puts one short paragraph on a
surface agents read during authoring, and links the contract rather than
restating it.

1. Add the instruction to `templates/rules/knowledge-persistence.md`, which
   already tells an agent where knowledge belongs.
2. Keep it to the invariant plus a pointer to ADR-110, so the rule gains a few
   lines rather than a copy of the contract.
3. Regenerate the rule mirrors through the pipeline.

**Exit**: an agent reading the placement rule learns to declare a dependency
instead of copying, and the always-on instruction budget moves by a few lines.

## Risks

1. A harness warns on an unfamiliar nested frontmatter key. Mitigation: 37 skill
   templates already carry free-form keys under `metadata` with no warning.
2. The conversion thins a safety control. Mitigation: each consumer keeps a
   one-line MUST, and the milestone runs the security review axis.
3. Milestone 3 touches more than ten files because the policy has 13 authored
   locations plus their projections. Mitigation: the change is mechanical and
   generator-driven, and the pull request body states the count and the reason.
