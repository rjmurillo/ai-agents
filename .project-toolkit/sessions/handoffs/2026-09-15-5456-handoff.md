## Lessons from M4 PR3 review (apply to PR4 and later)

- A skill `resources/` or `references/` file is not auto-loaded. The pointer line must say "Read X before Y", not "findings follow X".
- The spec skill body has a 200-line ceiling pinned by `tests/test_validation_skill_size.py`. Partials that push it over go to `references/` with a read instruction instead.
- Any clause that governs headless runs of every skill (the Unattended Runs clause) is cross-cutting and stays always-on.
- Corpus figures are pinned in four places (doctrine, rule-audit procedure, canonical-source-mirror rule, always-on-membership memory). Every byte change to an always-on rule needs all four refreshed. The rule-audit procedure test pins which rules may carry a byte figure (code-quality, pragmatic-programmer, voice); do not add another.
- An ADR edit needs a debate log staged under `.project-toolkit/critique/` with "debate" in the file name.
