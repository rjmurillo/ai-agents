# adr-review debate log: issue #5154 hook retirement

**Scope**: the 2026-08-18 amendments to ADR-068, ADR-071, ADR-082, and ADR-085
made under issue #5154, which deleted three tool-use hooks from the vendored
plugin surface: `invoke_push_pr_script_identity_guard.py` and its nine
`_push_pr_guard_*` companions, `invoke_markdownlint_guard.py` and the orphaned
`push_guard_base.py`, and `invoke_markdown_auto_lint.py`. Only
`invoke_require_subagent_model.py` survives.

**Panel**: architect, critic, independent-thinker, security, analyst,
high-level-advisor. Two rounds. Consensus reached in round 2.

## Round 1: 3 BLOCK, 3 disagree-and-commit

No consensus. The blocks converged on one point.

Two round-1 findings were checked and not acted on. The advisor reported that

The analyst could not execute commands and marked several checks

## Owner rulings

The repository owner resolved the block on 2026-08-18.

1. **The guard deletion stands, re-founded on the owner's security judgment.**
   ADR-084's ROI bar is not the warrant. The carve-out is quoted and complied
   with by changing the warrant rather than arguing the carve-out away. The
   authority is the disposition power ADR-085 Decision 7 gate 8 already assigns
   to the owner.
2. **The markdown deletions stand on a placement judgment**: linting belongs in
   Git hooks and lefthook, not on the per-tool-call path. Recorded as
   Decisions 9 and 10, each with owner classification, rationale, residual risk,
   and reversibility.
3. **The `guard-maturity` stack is retired in the same change** rather than left
   labelled as producerless.

### A disputed fact, settled from source

Two reviewers disagreed on whether `invoke_markdownlint_guard.py` self-neutered
in consumer repos. The source decides it. `run_guard` opened with:

```python
    if skip_if_consumer_repo(name):
        return 0
```

and `invoke_markdownlint_guard.py`'s `main` was `return run_guard(_validate,
["*.md"], GUARD_NAME)`. The guard returned 0 before reading stdin in any
consumer repo, so it never invoked `markdownlint-cli2` there. It was a standing
ADR-084 rule 4 violation and its consumer coverage was already zero.
`.agents/critique/ADR-084-debate-log.md:17` records the opposite; that
verification was wrong.

`invoke_markdown_auto_lint.py` had no such gate and did run in consumer repos,
so the drop to zero consumer coverage is real for the auto-fixer alone. ADR-085
Decision 10 owns that consequence in those terms rather than implying continuity.

## Disposition

Accepted. The round-1 blocks were text and warrant defects, not architecture
reversals, and all three are resolved in round 2. The dissent worth carrying
forward is the advisor's: watch for a prompt-injection incident routed through a
`new_pr.py` lookalike, because reintroduction now requires a new architecture
decision with a narrower matcher than bare `Bash`, per ADR-085's reversibility
clause.
