## What was validated

This change ships no code, so the QA question is not "does it run" but "is every load-bearing claim true." Both ADRs argue from measurements of this repository, and a false measurement would propagate into an implementation that removes real gates. Every factual claim was checked against a primary source, and review found six that were checked against the wrong source, the wrong unit, or not at all: #5099 read from a retrospective written the day before its fix merged; the claim that the labeled population could not be enumerated; two citation sets invalidated by a base merge; the commit-gate contract, which counts authored non-merge commits and relieves to 40 after a base merge rather than blocking flat at 20; and the reach of a stolen `BOT_PAT`, which mints approvals but cannot mutate a ruleset from a write-role account. All six are corrected below. This report records the misses rather than only the checks.

## Adversarial review

Seven rounds of six-role review, plus continuing bot review on the live pull request. The council decision at round 6 was 3 Accept, 3 Disagree-and-Commit, 0 Block on the round-6 text. Round 7 re-ran all six roles with tree-verification assigned to each and returned 1 Accept, 5 Disagree-and-Commit, 0 Block on `a6bfda1b6`. Both are consensus under this repository's contract, and both are review verdicts rather than acceptances.

**Neither consensus covers the current ADR heads, and an earlier revision of this report implied one did.** Bot review continued after each panel round and forced material change every time, most recently a fourteen-thread round that produced the transport-deviation concession, the agent-runtime credential class, the CODEOWNERS evidence withdrawal, the base-update attestation gap, and the two telemetry prerequisites. The contract requires consensus on the revision being accepted, so this report does not claim one for the current text. Both ADRs remain proposed. `governance.md` is scoped to `.agents/governance/**`, so MUST-1 and MUST NOT 1 bind the implementation pull requests rather than these proposals. Verdicts are recorded in `.agents/critique/ADR-100-101-enforcement-planes-debate-log.md`.

The review was load-bearing rather than confirmatory. It changed the design twice and falsified six factual claims:

1. **The deadlock mechanism was wrong.** A job-level `if:` skip satisfies a required check rather than deadlocking it, and this repository already ships that shape, including on a required context.
2. **The fix to that was itself spoofable.** Requiring a published `head_sha` status is defeated by a head-defined run with `statuses: write` posting the same context name, because rulesets match by context only while no publisher is pinned.
3. **ADR-100 would have shipped a tightening inside a subtraction**, removing the only relief from a gate that still blocks at 51 files.
4. **Issue #5099 was already fixed**, by merged PR #5146 two days before the ADR was written.
5. **The claim that the labeled population could not be enumerated was false.** A reviewer supplied the query.
6. **The "6 Accept, 0 Block" tally was unsupported**, because round 4 re-ran only four of six roles.

Worth recording for how this repository weighs its own review: every round-5 correction came from bot review of the live pull request, not from the agent panel. Round 7 tested the cheaper explanation for that, by assigning tree-verification to every role, and it found real defects in text eleven bot rounds had passed. So the panel's prior blindness reads as a missing role assignment rather than as single-vendor correlation.

A later round produced a sharper version of the same lesson, and it is a miss shared by every reviewer rather than by one of them. Six panel rounds and eleven bot reviews all accepted the stated limitation that a pull request the ceiling deterred, split, or squashed leaves no artifact any query can reach. That was true of GitHub and false of this repository, whose session protocol requires agents to write down what they did. A `grep` over three directories returns eight such cases across seven months. The corpus was in the working tree for every round. Nobody searched it, because the limitation had already been agreed to.

The last two findings are the same shape one level down, and neither came from a review pass. The skipped-gate finding came from a stop-time check asking whether the working tree was clean. The enforcement-ordering finding came from CI going red on this pull request for a reason nobody had predicted.

## Known limitations

- **The closed-unmerged population is now fully enumerated.** All seven were characterized. None was stopped by the size ceiling, and because #4846 carried the bypass label the population contains no pull request the blocking ceiling actually stopped. The residual limitation is survivorship: pull requests the ceiling deterred or that were split before opening appear in no query.
- **The review panel is single-vendor.** All six roles pin Anthropic models, so correlated blind spots are not addressed. Recorded in ADR-101 as accepted residual risk. Round 7 supplies evidence that an unassigned verification role accounts for more of the observed misses than vendor correlation does.
- **The scope gate's blocking record is unmeasurable, and the 90 day replay cannot reach it either.** `detect_scope_explosion.py` is invoked only from `lefthook.yml`, applies no label, and leaves no remote artifact, so no counterexample search is possible. A reviewer then showed the falsification predicate replays only the CI commit ceiling, so it cannot test the scope or atomic retirements at all. ADR-100 states that and offers the split.
- **The eight recovered workarounds are not a sample.** They have no stated selection method. They establish that the deterred population is non-empty. They cannot support a rate, and neither ADR claims one.
- **Item 6 is not yet buildable.** It names no telemetry sink, no auth model, no retention, and no failure policy, and its newest field cannot be emitted from the function it instruments, because a skipped job never enters it. ADR-100 records both as prerequisites.
- **The transport deviation is unresolved and is the owner's to dispose of.** It is recorded, not remediated: the content is already on the remote, so the action MUST NOT 2 prescribes, handing the branch back, is no longer available.
- **This report's own subject was a finding, twice.** Two revisions of the session log recorded a blocking Serena requirement at level SHOULD, and this report's ADR-numbering row carried a stale "next free 100" after the renumbering made it 102. Neither was caught by a gate; both were caught by review.
- **Two of an earlier round's findings were defects this session introduced.** The fork consequence and the `post-pr-retrospective.yml` grouping were both created by earlier corrections in this same sequence. A review process that only measures inbound findings would score those rounds as improvements.
- **No implementation was validated**, because none was written. Both ADRs are proposals; their implementation pull requests carry their own QA obligations.
