## Why `act` cannot supply the runtime evidence

The two review threads asked for a local `act` run against a `reopened` payload.
That run is not obtainable, and the reason is a property of `act` rather than of
this environment. Measured with `act` 0.2.89 and Docker 29.7.2: a payload with
`"action": "labeled"`, which is absent from both workflows' `types:` lists, runs
the job exactly like the `reopened` payload does. `act` filters on event name,
where `act push` correctly reports `Could not find any stages to run`, but it
does not evaluate `types:`.

So a green `act` run on a reopened payload would assert only that `pull_request`
is in the trigger list. That was true before this change and stays true if
`reopened` is removed again, which makes the run unable to fail for the reason
the change exists. `tests/workflows/test_pull_request_reopened_triggers.py`
parses the `types:` list directly and does fail when the entry is removed, so it
is the stronger evidence here, on exactly the axis `act` is blind to.

This supersedes the Docker-state note above as the reason `act` did not run.
