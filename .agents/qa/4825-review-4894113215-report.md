### Self-review finding: brace ranges failed closed

Probing ordinary brace usage after the gate landed measured 4 of 7 legitimate
commands denied: `cp file{1..1000}.txt dir/`, `mv report{1..200}.csv archive/`,
`touch log{0..99}.txt`, `echo {1..10000}`. Materializing a range exceeded the
expansion budget, and the budget fails closed. This was the reported defect in
a narrower band and would have shipped.

Fixed by collapsing a range to the characters the target can use instead of
enumerating it. Re-probed:

| Measurement | Before | After |
|-------------|--------|-------|
| Legitimate brace commands denied | 4 of 7 | 0 of 7 |
| Range-obfuscated attempts leaked | 0 of 8 | 0 of 8 |

Both bands are regression tests:
`test_dispatchers_allow_legitimate_brace_expansion` and
`test_dispatchers_deny_range_obfuscated_new_pr`.

### Resource bounds

Worst case over brace bombs, a 128 KiB payload, deep nesting, 500 operand
tokens, and device operands (`/dev/zero`, `/proc/self/mem`) is 0.103s against
the 10s hook timeout. Reads are gated by a size pre-check, so a device or FIFO
operand is rejected on `stat` and never opened. No `shell=True`, `eval`, or
`os.system` in either changed production file; every subprocess argv is a list.

### Accepted residual

A command that reconstructs the path at runtime without naming it is outside
the detection surface. The guard bounds the identity of named push-pr
invocations; it is not a Python or shell sandbox. An actor able to run
arbitrary code does not need `new_pr.py` to open a pull request. Recorded in
the guard module docstring, in `probe-evidence.md` section 7a, and pinned by a
test so it stays a decision rather than a discovery.
