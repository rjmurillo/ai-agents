### Self-review finding: brace ranges failed closed

Probing ordinary brace usage after the gate landed measured 4 of 7 legitimate
commands denied: `cp file{1..1000}.txt dir/`, `mv report{1..200}.csv archive/`,
`touch log{0..99}.txt`, `echo {1..10000}`. Materializing a range exceeded the
expansion budget, and the budget fails closed. This was the reported defect in
a narrower band and would have shipped.

Fixed by collapsing a range to the characters the target can use instead of
enumerating it. Re-probed:

### Resource bounds

Worst case over brace bombs, a 128 KiB payload, deep nesting, 500 operand
tokens, and device operands (`/dev/zero`, `/proc/self/mem`) is 0.103s against
the 10s hook timeout. Reads are gated by a size pre-check, so a device or FIFO
operand is rejected on `stat` and never opened. No `shell=True`, `eval`, or
`os.system` in either changed production file; every subprocess argv is a list.

### Round 2 follow-up: Python 3.10 floor (CONFIRMED)

Copilot flagged `hashlib.file_digest` at line 880. It landed in Python 3.11,
while the generated launchers accept any interpreter at 3.10 or newer.

Reproduced on cpython 3.10.20 against the canonical push-pr command:

```text
AttributeError: module 'hashlib' has no attribute 'file_digest'
EXIT=1
```

Exit 1 is a hook error to a PreToolUse host, not a block, so on that
interpreter the identity gate printed a traceback and stopped enforcing.

Fixed with a chunked sha256 read loop at both digest sites. Verified on
cpython 3.10.20 after the fix:

| Command | Expected | Actual |
|---------|----------|--------|
| canonical `python3 -I <runtime>/new_pr.py ...` | 0 | 0 |
| `python3 -I attacker/pr/new_pr.py` | 2 | 2 |
| `git status && git diff` | 0 | 0 |

No traceback on any. Pinned by
`test_guards_run_on_the_minimum_supported_interpreter` (real 3.10 subprocess,
both surfaces, skips when absent) and
`test_guards_do_not_use_post_310_hashlib_api` (always runs).

### Round 3: recursive review on the pushed head

Three further findings, each verified before the prescribed fix was applied.

**Stepped brace range (CONFIRMED, defect in the round 2 fix).**
`_brace_alternatives` split the body on the first `..` only, so
`{e..e..1}` left a three-part body that fell through to the comma branch and
became literal text. Bash expands `./attacker/pr/n{e..e..1}w_pr.py` to the
lookalike; a direct launch has no Python operand and bytes that differ from the
trusted script, so scope rules B and C both miss.

| Command | Before | After |
|---------|--------|-------|
| `./attacker/pr/n{e..e..1}w_pr.py` | exit 0 (leak) | exit 2 |
| `./attacker/pr/n{e..e}w_pr.py` | exit 2 | exit 2 |

Re-probed at 0 of 9 naming forms leaked and 0 of 6 legitimate brace commands
falsely denied.

**`-I` disabled every timed shim (CONFIRMED, product defect from this PR).**
`run_timed_shim` launched shims with `-I`, which implies `-P` and drops the
script's directory from `sys.path`, while every timed shim imports its sibling
`_bootstrap`:

```text
File ".../invoke_markdownlint_guard.py", line 23, in <module>
    from _bootstrap import ensure_plugin_paths
ModuleNotFoundError: No module named '_bootstrap'
```

The child died before its policy ran, so the markdownlint push guard was
disabled at runtime on both harnesses. I had seen this failure through a
dispatcher earlier in this session and wrongly filed it as a test-harness
artifact; the review was right that it is the shipped launcher.

Fixed with `-E -s`, which keeps the injection protection without dropping the
script directory. Verified: an attacker directory on `PYTHONPATH` stays off the
child's `sys.path` under `-E -s` and reaches it without the flags (negative
control), and both dispatchers now run the guard end to end with no traceback.

**Unrestricted `Write` grant (CONFIRMED).** This PR added bare `Write` to
`/push-pr` alongside `git add`, `git commit` and `git push`, on a command that
reads untrusted diffs. The version this PR started from instructed the same
body write with no `Write` grant, so the grant was not needed. Removed; the
narrow `Bash(mkdir:-p .agents/scratch)` grant stays.

### Accepted residual

A command that reconstructs the path at runtime without naming it is outside
the detection surface. The guard bounds the identity of named push-pr
invocations; it is not a Python or shell sandbox. An actor able to run
arbitrary code does not need `new_pr.py` to open a pull request. Recorded in
the guard module docstring, in `probe-evidence.md` section 7a, and pinned by a
test so it stays a decision rather than a discovery.
