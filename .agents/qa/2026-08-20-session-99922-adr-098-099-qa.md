## What was validated

This change ships no code, so the QA question is not "does it run" but "is every load-bearing claim true." Both ADRs argue from measurements of this repository, and a false measurement would propagate into an implementation that removes real gates. Every factual claim was checked against a primary source, and review found six that were checked against the wrong source, the wrong unit, or not at all: #5099 read from a retrospective written the day before its fix merged; the claim that the labeled population could not be enumerated; two citation sets invalidated by a base merge; the commit-gate contract, which counts authored non-merge commits and relieves to 40 after a base merge rather than blocking flat at 20; and the reach of a stolen `BOT_PAT`, which mints approvals but cannot mutate a ruleset from a write-role account. All six are corrected below. This report records the misses rather than only the checks.

## Adversarial review

Six rounds of six-role review, plus four independent bot reviews on the live pull request. The council decision is 3 Accept, 3 Disagree-and-Commit, 0 Block: consensus under this repository's contract, and a review verdict rather than an acceptance. Both ADRs remain proposed. `governance.md` is scoped to `.agents/governance/**`, so MUST-1 and MUST NOT 1 bind the implementation pull requests rather than these proposals. Verdicts are recorded in `.agents/critique/ADR-098-099-enforcement-planes-debate-log.md`.

The review was load-bearing rather than confirmatory. It changed the design twice and falsified six factual claims:

1. **The deadlock mechanism was wrong.** A job-level `if:` skip satisfies a required check rather than deadlocking it, and this repository already ships that shape.
2. **The fix to that was itself spoofable.** Requiring a published `head_sha` status is defeated by a head-defined run with `statuses: write` posting the same context name, because rulesets match by context only.
3. **ADR-098 would have shipped a tightening inside a subtraction**, removing the only relief from a gate that still blocks at 51 files.
4. **Issue #5099 was already fixed**, by merged PR #5146 two days before the ADR was written. The draft treated it as a live CVSS 8.8 hole because it read a retrospective written the day before the fix landed.
5. **The claim that the labeled population could not be enumerated was false.** A reviewer supplied the query.
6. **The "6 Accept, 0 Block" tally was unsupported**, because round 4 re-ran only four of six roles.

Worth recording for how this repository weighs its own review: every round-5 correction came from bot review of the live pull request, not from the agent panel. The panel converged; the external reviewers kept finding errors. That is the correlated-blind-spot risk the single-vendor limitation predicts, observed rather than theorized.

A later round produced a sharper version of the same lesson, and it is a miss shared by every reviewer rather than by one of them. Six panel rounds and eleven bot reviews all reasoned about the size ceilings from GitHub label populations, and all of them accepted the stated limitation that a pull request the ceiling deterred, split, or squashed leaves no artifact any query can reach. That was true of GitHub and false of this repository, whose session protocol requires agents to write down what they did. A `grep` over `.agents/qa/`, `.agents/sessions/`, and `.agents/retrospective/` returns eight such cases across seven months, including the two squashes on PR #5178 that made eleven cited review SHAs unreachable. The corpus was in the working tree for every round. Nobody searched it, because the limitation had already been agreed to. A limitation accepted early is not re-tested later by any of the mechanisms this repository runs.

## Known limitations

- **The closed-unmerged population is now fully enumerated.** All seven were characterized, including #4814 (13 commits) and #4733 (11 commits), read in the final round. None was stopped by the size ceiling, and because #4846 carried the bypass label the population contains no pull request the blocking ceiling actually stopped. Earlier note, retained for the record: An earlier revision of this report claimed the tooling could not list pull requests by label. That was false. `label:"needs-split" created:2026-08-06..2026-08-20 is:closed is:unmerged` returns seven; exactly one carries `commit-limit-bypass`, and five of the seven were characterized directly. No counterexample was found. Two of the seven were not read. The residual limitation is survivorship: pull requests the ceiling deterred or that were split before opening appear in no query.
- **The review panel is single-vendor.** All six roles pin Anthropic models, so correlated blind spots are not addressed. Recorded in ADR-099 as accepted residual risk.
- **The scope gate's blocking record is unmeasurable, and ADR-098 now says so.** `detect_scope_explosion.py` is invoked only from `lefthook.yml:378` and `:542`, never from a workflow, and applies no label, so a pull request it blocked leaves no remote artifact. The counterexample search that was possible for the commit ceiling cannot be run for it. Its retirement therefore rests on shared provenance with the commit ceiling through ADR-049, the unverified bypass flag, and one first-hand false positive, which is weaker than what items 1 and 2 rest on. ADR-098 states that and offers the split.
- **The eight recovered workarounds are not a sample.** They have no stated selection method: they are what `grep` reached in records an agent chose to write. They establish that the deterred population is non-empty. They cannot support a rate, and neither ADR-098 nor this report claims one.
- **Two of this round's findings were defects this session introduced, not pre-existing ones.** The fork consequence and the `post-pr-retrospective.yml` grouping were both created by earlier corrections in this same review sequence. A review process that only measures inbound findings would score those rounds as improvements. They were regressions caught by the next pass, and the debate log records them as such.
- **No implementation was validated**, because none was written. Both ADRs are proposals; their implementation pull requests carry their own QA obligations.
