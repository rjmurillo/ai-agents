# OntologyFragment: skill guidance excerpts

Source: issue #5706 (epic #5698). Elicited 2026-09-11 from the issue body, ADR-107, REQ-003, and the current build tree.

## O1 Entities and value objects

| Entity | Kind | Where it lives today |
|---|---|---|
| Rule file | entity | `.claude/rules/<name>.md`, canonical, hand-maintained |
| Always-on rule set | value object | the five rule files whose frontmatter is `paths: ["**"]` |
| Canonical skill file | entity | `.claude/skills/<name>/SKILL.md` for a skill with no template: canonical, hand-maintained (REQ-003 decision D4) |
| Skill mirror | entity | `src/copilot-cli/skills/<name>/SKILL.md`, generated by `build/scripts/generate_skills.py` |
| Skill template | entity | new: `templates/skills/<name>.SKILL.md.tmpl`, canonical for a template-owned skill |
| Partial | entity | new: `templates/skills/partials/<slug>.mustache`, a verbatim contiguous excerpt of one rule file when pinned by `{{! rule-source: <file>.md }}` |
| Template-owned skill file | entity | `.claude/skills/<name>/SKILL.md` when a template exists for `<name>`; derived, loaded by Claude Code, mirrored by the existing copy |
| Compile step | entity | new: `build/scripts/skill_templates.py`, called by `generate_skills.py` and `build_all.py` |
| Drift gate | entity | `generate_skills.py --validate`, `build_all.py --check`, and the `Skill Template Drift` row in `pre_pr_sequence.py` |

| Include line | value object | the literal line `@CLAUDE.md`; Claude Code resolves it, Copilot CLI treats it as literal text |

## O2 Ubiquitous language (canonical names)

- **rule file**, not "always-on file" or "instruction".
- **skill template**, the `.tmpl` file; **template-owned skill file**, its rendered output; **canonical skill file** only for a skill with no template.
- **partial**, never "excerpt" or "snippet"; its pin is the **rule-source**.
- **compile step** for the render; **drift gate** for the validate mode and its `pre_pr` row.
- **pilot skill**, the eight named skills.
- Retired names from the declined design: "excerpt block", "parity gate", "`--fix`".

## O3 Relationships

- A rule file contains zero or more spans that a partial copies verbatim.
- A partial names exactly one rule file as its source, or none once that rule text has been cut.
- A skill template references zero or more partials by slug; a slug resolves to exactly one partial file.
- The compile step renders a template into its template-owned skill file; the drift gate compares the render to the committed file.
- The skill mirror is derived from the template-owned skill file by the existing generator, unchanged.

## O4 Aggregate boundaries

- Aggregate root: the skill template. Its rendered file is derived and owns nothing.
- Aggregate root: the partial. Its `rule-source` pin is part of it.
- The rule file is outside both aggregates and is never written by this work.

## O5 Decision rules

- DR1: a template-owned skill file MUST equal the render of its template byte for byte.
- DR2: a partial with a `rule-source` MUST appear verbatim and contiguously in that rule file.
- DR3: the build writes under `.claude/` only to template-owned skill files enumerated at run time from `templates/skills/`; every other write is a REQ-003-010 violation (ADR-108).
- DR4: a template-owned skill file carrying a NO-REGEN sentinel (any of the three forms `regen_guard.py` recognizes) is never overwritten; the skip is reported at WARN and the compile exits 1 in write and validate mode (ADR-108 section 4).
- DR5: a skill with no template is untouched by the compile step.
- DR6: a template contains only partial tags and comment tags; any other tag is a configuration error.

## O6 Bounded contexts

- Rule authoring (`.claude/rules/`): unchanged by this work.
- Skill authoring: for a pilot skill, moves to `templates/skills/`; the rendered file is not hand-edited.
- Generation (`build/scripts/`): gains the compile step and the `chevron` dev dependency; the guard gains a run-time allowlist.
- Validation (`scripts/validation/`): gains the drift gate row.
