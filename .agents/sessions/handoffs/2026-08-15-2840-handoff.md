## Context for Next Session

- Two distinct, differently-computed session-log validation modes exist in this repo and must not be conflated: the local lefthook pre-push gate (`git_hook_policy.py sessions`, via `session_change_scope()`) and the actual CI workflow (`validate_session_protocol.py`, via `committed_session_validation_modes()`). A session log can pass the former (bypassed compliance) while genuinely failing the latter (strict full mode). See `.serena/memories/session-protocol/ci-vs-local-mode-discrepancy.md` for the full writeup.
- The MUST-to-SHOULD demotion mechanism in `validate_session_json.py` requires a non-empty `Evidence` string documenting the justification; an absent `level` field is a separate, harder failure. Never leave `level` unset when demoting.
- `QA_EVIDENCE_PREFIXES` (`.agents/memory/episodes/`, `.agents/qa/`, `.agents/sessions/`) governs staleness: any file changed outside these three prefixes, between a QA report's bound commit and the live PR head, stales every session whose QA report lists that file as evidence this scope covers. Editing `.agents/analysis/2026-08-12-adr-080-copilot-model-resolution.md` (an evidence path but not a QA-evidence-prefix path) has now triggered this twice (`9996e0905`, then indirectly required the round-4 fix above); any future edit to that file requires rebinding both QA reports again, in the same commit.
- `extract_session_episode.py --preserve` can silently duplicate commit events when the episode already stores the same commit at a different SHA abbreviation length than what fresh prose extraction produces. It is safe when the commit is genuinely new to the episode (no existing representation at any length), which is the case handled by this round's fixes; always diff before/after and check `metrics.commits` before trusting `--preserve` output when a commit might already be partially represented.
- This PR's established "content-fix-then-rebind" pattern continues: a content commit lands first, then a later commit updates `endingCommit`/`qaCommit` to reference the earlier commit's own SHA. When a rebind commit's own prose narrates who did the rebind, name the commit and QA-report revision history directly.
