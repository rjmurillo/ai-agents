# ADR-109: Template-First Plugin Distribution

## Status

Proposed (2026-09-11). The repository owner directed this shape on 2026-09-11: move every artifact class the plugins ship (agents, skills, rules, hooks, settings) under `templates/`, compile them into two plugin trees, and bin-place those trees into the two hand-edited install locations, as one atomic operation. This record inverts ADR-052's Claude-first direction, generalizes ADR-108's compile-and-drift-gate pattern from one enumerated skill class to every class, and amends ADR-107 settled property 1, REQ-003 D4, and REQ-003-010 for the same reason ADR-108 amended them, applied to more trees. Nothing below is implemented yet.

This record supersedes ADR-052 on acceptance, not at proposal. Its frontmatter carries `supersedes: []` until then, and ADR-052 stays `status: accepted` with a Status note naming this record, because `scripts/validation/check_adr_lifecycle.py:72` refuses a proposed record that declares `supersedes` (`repo-observed`: with `supersedes: [ADR-052]` set, the gate reported `proposed-cannot-supersede: 0 -> 1` on 2026-09-11). The B0 text amendments to ADR-052, ADR-107, REQ-003, and the ADR index are staged with this record as conditional clauses that each name this record as proposed; section 5 and section 6 say which words change at acceptance.

## Context

Six artifact surfaces exist across three install locations today: `templates/agents/*.shared.md` (31 files, `repo-observed`: `ls templates/agents/*.shared.md | wc -l`), `src/claude/`, `.claude/agents/`, `.github/agents/` for agents; `.claude/skills/<name>/SKILL.md` for skills, of which 18 of 111 render from `templates/skills/<name>.SKILL.md.tmpl` under ADR-108 and 93 remain hand-maintained (`repo-observed`: `ls templates/skills/*.tmpl | wc -l` against `find .claude/skills -maxdepth 2 -name SKILL.md | wc -l`); `.claude/rules/*.md` (30 files, `repo-observed`: `ls .claude/rules/*.md | wc -l`) with no `templates/rules/` tree at all (`repo-observed`: `ls templates/rules` fails, no such directory); and `.claude/hooks/` (23 files across six event directories, `repo-observed`: `find .claude/hooks -type f | wc -l`) plus `.claude/settings.json`, neither templated. `.github/hooks/` does not exist in this tree (`repo-observed`: `ls .github/hooks/` fails), yet the official Copilot CLI hook contract lists `.github/hooks/*.json` as the repository hook location (`docs-say`, `.claude/skills/agent-harness-reference/references/official-hook-contracts.md:48`, Configuration contract table) and states that the cloud agent "loads only `.github/hooks/*.json`" and "does not load user settings, repository settings, or installed plugins" (`docs-say`, same file, `:291-299`, Cloud agent section). The plugin hook channel carries no registration today: `.claude/hooks/hooks.json` and `src/copilot-cli/hooks/hooks.json` both read `"hooks": {}` since ADR-097 retired the last plugin-registered event (`repo-observed`, both files read verbatim; `.agents/architecture/ADR-097-zero-tool-use-hooks.md:96-98`).

Of these, only agents (ADR-052, accepted 2026-08-25, zero implementation) and skills (ADR-108, accepted 2026-09-11, 18 of 111 skills) have an amendment path already recorded. `.claude/rules/claude-agents.md:24` measures why the agent gap is not cosmetic: of 173 commits since 2025-01-01 touching a hand-maintained member of a shared-agent group, 54 (31%) did not touch the corresponding template, and the co-change gate that exists is asymmetric, catching a solo template edit but not a solo `src/claude/` edit (`repo-observed`, same line, with the exact commands and exit codes that demonstrate the asymmetry).

The lib surface is a fourth, narrower case. `scripts/{hook_utilities,github_core,ai_review_common}/` are Python packages with absolute imports; `scripts/sync_plugin_lib.py` copies them into `.claude/lib/` with relative imports, and `build/scripts/build_all.py` separately mirrors `.claude/lib/` into `src/copilot-cli/lib/`. `.claude/rules/generated-artifacts.md`'s "Generator order: sync before build" section names the hazard directly: the two scripts do not call each other, both exit 0 regardless of order, and running them out of order leaves `src/copilot-cli/lib/` mirroring stale content with no local signal, caught only by `scripts/ci/check_plugin_lib_mirrors.py` in CI (`docs-say`, `.claude/rules/generated-artifacts.md:159-197`). That same section explicitly forbids the obvious fix: "Do not resolve this by having `build_all.py` invoke `sync_plugin_lib.py`. REQ-003-010 forbids generators from writing under `.claude/`" (`docs-say`, same file, line ~193-197). Moving `scripts/github_core/`, `scripts/hook_utilities/`, and `scripts/ai_review_common/` under `templates/` would break their absolute imports: the three packages carry 39 `from scripts.<pkg>` import lines across 17 of their own files, and 138 files outside them carry 263 more (89 under `tests/`, 31 under `scripts/`, 13 under `.github/`, 5 under `.claude/hooks/`, none under `build/`) (`repo-observed`: regex `^\s*(from|import)\s+(scripts\.)?(github_core|hook_utilities|ai_review_common)\b` over `*.py` under `scripts/`, `build/`, `tests/`, `.claude/hooks/`, and `.github/`, excluding `.claude/lib/`). The `.claude/lib/` copies carry 40 relative imports instead, which is the rewrite `scripts/sync_plugin_lib.py` performs on copy. Docstrings also name the current path, for example `scripts/github_core/comment_classification.py:10`.

Two hand-maintained install locations receive these compiled outputs: `.claude/` (Claude Code plugin, per `.claude/rules/plugin-self-containment.md`) and `.github/` (the Copilot mirror trees `.github/instructions/`, `.github/agents/`, and the not-yet-existing `.github/hooks/`). `.claude-plugin/marketplace.json` names two Claude-side plugins today, `claude-agents` at `./src/claude` and `project-toolkit` at `./.claude` (`repo-observed`, file read verbatim); `.github/plugin/marketplace.json` names one Copilot-side plugin, `project-toolkit` at `./src/copilot-cli` (`repo-observed`, file read verbatim).

## Decision Drivers

- D1: owner directive, 2026-09-11. Templates for skills, agents, hooks, and settings go under `templates/`, integrate into the compiler, render into `src/claude/` and `src/copilot-cli/`, then bin-place into `.claude/` and `.github/`, as one atomic operation, so the repository dogfoods what it ships.
- D2: no content-agreement gate on agents. `.claude/rules/claude-agents.md:24` measures 54 of 173 commits (31%) touching a hand-maintained shared-agent member without touching its template; the existing co-change gate is asymmetric and does not catch it.
- D3: the lib mirror is a two-hop chain with a documented, currently-unenforceable ordering hazard, and the rule text that names it explicitly forbids the naive fix of having `build_all.py` call `sync_plugin_lib.py` because REQ-003-010 forbids a generator writing under `.claude/` outside the enumerated exceptions (`.claude/rules/generated-artifacts.md:159-197`).
- D4: ADR-052 was accepted 2026-08-25 as target architecture and remains at zero implementation (`docs-say`, ADR-052 Status: "Not implemented. All three Migration Plan phases below are outstanding"). A second unimplemented direction is a cost only if this record supersedes rather than stacks; see Alternative A below for why it must supersede.
- D5: ADR-108 proved the compile-plus-drift-gate shape delivers: three PRs merged 2026-09-11 (`repo-observed`, `git log --oneline`: `5159f30da` #5724, `02f7a589b` #5726, `8a79d7e83` #5731), plus two more skill-templating PRs the same day (`fcc5ea0cc` #5739, `915281c25` #5740), taking the templated-skill count from 8 to 18 without a second design.
- D6: Copilot CLI's repository hook location is `.github/hooks/*.json` (`docs-say`, `.claude/skills/agent-harness-reference/references/official-hook-contracts.md:48`); the cloud agent loads only that file and ignores installed plugins (`docs-say`, same file `:291-299`); this repository does not populate it, and both plugin `hooks.json` files register nothing (Context above, ADR-097). So hook distribution to this repository's own Copilot sessions and cloud-agent runs is a gap this record closes, not a tree it migrates off an existing generator. Plugin consumers gain a hook only when a template registers one, which is a B4 decision, not this record's.
- D7: `.claude/rules/plugin-self-containment.md` names the self-hosting property directly: "This repository self-hosts its own plugins... every upstream reference resolves here," which is also why a wrong path or a stale hand-edit is invisible until a consumer installs the plugin fresh.

## Decision

Adopt template-first distribution for every artifact class the plugins ship, with one stated exception for imported Python library code, and supersede ADR-052 with an inverted direction.

### 1. Canonical source moves to `templates/`, per class

| Class | Canonical source | Current state |
|---|---|---|
| Agents | `templates/agents/*.shared.md` (already exists, 31 files) | Partially templated; `src/claude/` is hand-maintained today, not generated (ADR-036 §Source 1, ADR-052 not implemented) |
| Skills | `templates/skills/<name>.SKILL.md.tmpl` (already exists, ADR-108, 18 of 111 files) | Partially templated |
| Rules | `templates/rules/<name>.md` (new) | No template tree exists; `.claude/rules/*.md` (30 files) is fully hand-maintained and is itself the source `generate_rules.py` reads for the Copilot instruction mirrors |
| Hooks + settings | `templates/hooks/` (new) | No template tree exists; `.claude/hooks/` (23 files) and `.claude/settings.json` are hand-maintained and are the source `generate_hooks.py` reads for the Copilot mirror |
| Lib | `scripts/{hook_utilities,github_core,ai_review_common}/` (unchanged; exception, see below) | Already canonical; copied twice today through `.claude/lib/` as an intermediate hop |

Exception: lib's canonical source stays `scripts/`, not `templates/`. The packages carry absolute imports consumed by other modules under `scripts/` and `build/scripts/` at their current path; relocating them under `templates/` breaks every one of those imports with no compensating benefit, since lib ships as compiled Python, not rendered prose. The compiler absorbs the copy step instead of leaving it as a second, independently-invoked script: `build_all.py` copies `scripts/{hook_utilities,github_core,ai_review_common}/` directly into both `src/claude/lib/` and `src/copilot-cli/lib/` in the same run that renders every other class, and the binplace step (below) copies `src/claude/lib/` into `.claude/lib/` alongside the other bin-placed trees. `scripts/sync_plugin_lib.py` as a standalone, separately-invoked script is retired; its `SYNC_PAIRS` logic moves inside `build_all.py`'s lib step. The "sync before build" ordering hazard in `.claude/rules/generated-artifacts.md` dies because one command now performs both hops atomically; there is no longer a second script whose invocation order matters.

### 2. The compiler renders two plugin trees

`build/scripts/build_all.py`'s generators render templates into `src/claude/` (Claude Code plugin: `agents/`, `skills/`, `rules/`, `hooks/` plus `hooks.json`, `lib/`, `.claude-plugin/plugin.json`) and `src/copilot-cli/` (Copilot CLI plugin, its existing layout: `agents/`, `skills/`, `instructions/`, `hooks/`, `lib/`, `.claude-plugin/plugin.json`).

This changes `src/claude/`'s layout. Today its agent files sit flat at the plugin root, `src/claude/<name>.md`, with no `agents/` subdirectory (`repo-observed`: `ls src/claude`; `build/scripts/validate_install_parity.py:141` matches `^src/claude/(?P<name>[^/]+)\.md$`). B1 moves them to `src/claude/agents/<name>.md`, the layout `.claude/agents/` already uses, rewrites that regex and `detect_agent_drift.py`'s comparison pairs, and lands before the B6 marketplace switch. A consumer of the `claude-agents` plugin sees the path move at their next plugin update; B6 then retires that plugin name.

### 3. Binplace: one atomic operation writes the install trees

The same `build_all.py` run copies `src/claude/` into `.claude/` (agents, skills, rules, hooks, lib, plus `.claude/settings.json` rendered from the hooks template, which is repo-local dogfood configuration and ships in no plugin) and copies `src/copilot-cli/` into `.github/` (`instructions/`, `agents/`, and `hooks/` written as `.github/hooks/*.json`, the only path Copilot CLI's repository hook loader reads per D6). Two surfaces have no plugin stage because no plugin consumes them: `.claude/settings.json` (repo-local Claude Code configuration) and `.github/prompts/` (repo-local Copilot prompt files; `src/copilot-cli/` ships no `prompts/` directory today, `repo-observed`: `ls src/copilot-cli`). The binplace manifest carries those two as direct rows, template to install path, with the existing `build/scripts/generate_pr_quality_prompts.py` becoming the compile step for the `pr-quality-gate-*` prompt subset. Render and binplace are one command. `build_all.py --check` verifies all four output trees, `src/claude`, `src/copilot-cli`, `.claude`, and the manifest-named paths under `.github` (`instructions/`, `agents/`, `hooks/`, and the twelve `prompts/pr-quality-gate-*.md` files), are byte-identical to what the templates render; an edit to a template or partial is the only sanctioned way to change any file the manifest owns in any of the four trees. `.github/prompts/` is split, not whole: 33 files sit there and 12 are `pr-quality-gate-*` (`repo-observed`: `ls .github/prompts`), so the other 21 stay hand-maintained until a template names them. Files under `.github/` the manifest does not name (workflows, CODEOWNERS, the Copilot marketplace manifest, those 21 prompt files) stay hand-maintained. "One command" means write atomicity across the four trees, not live reload: a session that already loaded `.claude/settings.json`, a hook script, or an agent file keeps the old content until it restarts, the same behavior a hand edit has today.

### 4. One Claude plugin

`.claude-plugin/marketplace.json` drops the `claude-agents` entry (`./src/claude`) and repoints `project-toolkit` at `./src/claude`, replacing the current `./.claude` source. `claude-agents` is retired as a distinct plugin. `.claude/` stops being a plugin root in the marketplace manifest and becomes the dogfood copy the binplace step writes. The Copilot marketplace is unchanged: `project-toolkit` at `./src/copilot-cli`. `src/claude/.claude-plugin/plugin.json` becomes the `project-toolkit` manifest; `.claude/.claude-plugin/plugin.json` is deleted. Manifests carry no `version` field, unchanged from ADR-092.

### 7. Migration order

One PR series per class, in this order: agents, rules, remaining skills (93 not yet templated, measured above), hooks plus settings, lib, then the marketplace switch last, because it is the customer-visible cut. Agents go first because D2 measures the largest unguarded drift (31%) and D5 already proved the compile shape on skills, so B1 trades reuse-first for close-the-largest-gap-first, deliberately. A class is one unit of review and rollback, but it may land in batches when its file count exceeds ADR-108's per-PR precedent of five to eight files (#5731 shipped eight, #5739 and #5740 five each; the `File cap per PR` item at `.claude/rules/claude-agents.md:27` asks skill additions to ship at most 10 files per PR): B3's 93 skills are that case. Each PR keeps `build_all.py --check` green and keeps the parity and drift gates that predate it green until that class's own gate supersedes them; see Implementation Notes for which gate each PR retires or rewires.

## Prior Art Investigation

### What currently exists

- **Structure being changed**: the hand-maintained status of `src/claude/` (agents), `.claude/rules/` (rules), `.claude/hooks/` plus `.claude/settings.json` (hooks), and the two-hop `scripts/` to `.claude/lib/` to `src/copilot-cli/lib/` mirror (lib). Skills are partially changed already by ADR-108.
- **When introduced**: `src/claude/` as hand-maintained, non-generated Claude source: ADR-036, 2026-01-01, reaffirmed by ADR-052's Prior Art correction (2026-08-25) that ADR-036 never claimed Claude agents were generated. The `.claude/` no-write invariant, REQ-003-010: commit `c00a32e5f`, 2026-04-30, PR #1819 (`docs-say`, ADR-108 Prior Art, which cites the same commit). The lib mirror chain: issue #2613 (`docs-say`, `build/scripts/build_all.py:818` comment).
- **Original author and context**: `rjmurillo`, sole `decision-makers` entry across ADR-036, ADR-052, ADR-107, ADR-108 (`repo-observed`, frontmatter of each).

### Historical rationale

- **Why it was built this way**: REQ-003-010 exists so that "Customers editing any other path under `.claude/` directly shall not have their changes overwritten" (`docs-say`, `.agents/specs/requirements/REQ-003-multi-tool-artifact-build.md:360`; the words "any other path under" arrived with ADR-108's in-place amendment, and ADR-108 Prior Art quotes the earlier form, "Customers editing `.claude/` directly"). The 2025-12-15 incident an agent "fixed" a drift failure by editing the canonical source to match generated output, and the commit was reverted, is the cited origin of the one-direction rule (`docs-say`, ADR-108 Prior Art, citing `.claude/skills/ai-agents-change-control/SKILL.md`).
- **What alternatives were considered**: ADR-052 considered and selected Claude-first (Claude canonical, Copilot and VS Code derived) over template-first (the then-current model) and over independent per-platform maintenance, on the argument that a third tree (templates) alongside `src/claude/` and the derived outputs was excess maintenance surface for agents specifically. ADR-108 separately considered an in-file excerpt design (DESIGN-024) that needed no amendment, and the owner declined it in favor of template-owned skill files. Issue #1918 (closed 2026-06-03) proposed `templates/platforms/claude.yaml` so `build_all.py` would own `.claude/agents/` and `src/claude/`, and issue #2267 (closed 2026-06-04) asked the same for `.claude/agents/`, `.github/agents/`, and `src/claude/`; both were closed because REQ-003 D4 and REQ-003-010 forbade the write and `build/scripts/detect_agent_drift.py` declared Claude agents deliberately ungenerated (`docs-say`, the closing triage comments on each issue). This record amends both clauses, so the closure premise no longer holds, and B1 is the #1918 mechanism under the amended rule.
- **What constraints drove it**: REQ-003-010's one-direction rule; ADR-107 R3's ban on a second generation authority; the lib mirror's absolute-import constraint, which is new to this record and was not a factor in ADR-036, ADR-052, or ADR-108, none of which touch lib.

### Why change now

- **Has the original problem changed?** No for the invariant itself, source of truth must not invert. Yes for its scope: ADR-108 demonstrated the compile-and-drift-gate pattern closes the inversion risk for a generated class the same way the one-direction rule closes it for a hand-maintained one, and it did so for skills in one day across three PRs (D5).
- **Is there a better solution now?** ADR-052's Claude-first direction and this record's template-first direction cannot coexist for agents; ADR-052 has had 17 days at `accepted` status with zero implementation (2026-08-25 to 2026-09-11), while ADR-108's parallel pattern shipped in the same span it took to write this record. The owner's 2026-09-11 directive selects template-first for every class, which requires superseding ADR-052 rather than layering beside it.
- **Risks of change**: every class not yet templated (agents beyond the existing `templates/agents/`, all of rules, all of hooks and settings) moves its canonical location out of the file contributors currently edit; a contributor who does not know the class has moved loses a hand edit at the next build, the same risk ADR-108 named and mitigated for skills with a drift gate and a NO-REGEN sentinel. Mitigation here is the same mechanism, applied per class, plus the `GENERATOR-FILES.md` row each migration PR adds.

### Trade-offs

Every class not yet templated trades a direct-edit workflow for a compile-and-drift-gate workflow: slower to make a one-line change (edit template, run compiler, verify four trees), but the change is guaranteed to land in every consumer instead of only the tree someone happened to edit. The lib exception trades the notational cleanliness of "everything under `templates/`" for zero broken imports; keeping lib's source in `scripts/` accepts that one class of this record's "templates are canonical" story is stated as prose (this ADR, section 1) rather than enforced by directory placement, and the compile-plus-binplace pipeline is the actual enforcement instead.

## Consequences

### Positive

- One canonical source per class, enforced by a drift gate instead of a convention nothing checks, closing the exact gap D2 measures for agents.
- The lib mirror's ordering hazard is eliminated by construction: one script performs both hops in one run, so there is no second invocation whose order can be gotten wrong.
- This repository's own Copilot sessions and cloud-agent runs receive `.github/hooks/*.json` for the first time; that path does not exist in this tree today (D6), so this closes a real gap rather than migrating an existing generator. Plugin consumers gain a hook only when a hook template registers one; both plugin `hooks.json` files register nothing today (ADR-097).
- Every later skill, rule, or hook migrates by adding one template file; ADR-108 already proved this shape for skills across five PRs in one day.

### Negative

- 93 skills, all 30 rules, and all hooks plus settings move from a direct-edit workflow to a compile step, each requiring its own PR, its own drift gate, and its own `GENERATOR-FILES.md` row before the class is complete.
- Every contributor who currently hand-edits `.claude/rules/*.md`, `.claude/hooks/`, or `.claude/settings.json` loses the direct-edit path for that class once its PR lands; the drift gate and pre-PR sequence catch a stale hand edit only when they run before the next writing build does, the same window ADR-108 already accepted for skills.
- What contributors stop doing, per class, once its PR merges. B1: stop editing `src/claude/`, `.claude/agents/`, and `.github/agents/`; edit `templates/agents/<name>.shared.md`. B2: stop editing `.claude/rules/*.md`; edit `templates/rules/<name>.md`. B3: stop editing any `.claude/skills/<name>/SKILL.md`; edit `templates/skills/<name>.SKILL.md.tmpl`. B4: stop editing `.claude/hooks/` and `.claude/settings.json`; edit `templates/hooks/`. B5: keep editing `scripts/<pkg>/`; stop running `scripts/sync_plugin_lib.py`; run `build_all.py`. Until a class's PR merges, its current workflow stands.
- `.github/CODEOWNERS` grows: `templates/rules/` and `templates/hooks/`, mirroring the `templates/skills/` entry ADR-108 added; the binplace manifest under `templates/platforms/`, because that file defines the `.claude/` write allowlist and widening it needs owner review; and `scripts/hook_utilities/` and `scripts/github_core/` with their `.claude/lib/` copies, since B5 copies executable code the hooks run and only `ai_review_common` is pinned today (`.github/CODEOWNERS:20-21`). CODEOWNERS routes review; it blocks a merge only when the ruleset requires code-owner review, and the default-branch ruleset carries `require_code_owner_review: false` today (`.agents/critique/ADR-108-debate-log.md:378-383`). This record names that gap and does not assume it closed; whether to require code-owner review before B4 writes executable hook configuration is the owner's call, and B4's review records it.
- A template or partial change now regenerates up to four output trees in one diff (`src/claude`, `src/copilot-cli`, `.claude`, `.github`), producing larger reviewed diffs per change than a single hand-edited file did.
- `scripts/sync_plugin_lib.py` as a standalone entry point is retired; any contributor tooling or documentation that invokes it directly needs the equivalent `build_all.py` invocation instead.
- The `src/claude/` layout moves from flat agent files to `src/claude/agents/` in B1 (Decision section 2); every tool that matches the flat path changes with it.

### Neutral

- `src/vs-code-agents/` and its generator are untouched; this record does not extend to that platform.
- REQ-003 D8's conditional (custom instructions generation, pending verification Copilot CLI consumes `applyTo:`) is left exactly as written; this record found no new evidence to retire it.
- ADR-092 (no manifest version) is unaffected: the marketplace switch in section 4 edits `source:` paths and deletes one manifest file, not a version field.

The binplace manifest, which source path copies to which install path, is data, not code: a YAML file under `templates/platforms/` (alongside the existing `copilot-cli.yaml`, `visual-studio.yaml`, and `vscode.yaml`), read by `build_all.py`'s binplace step and by `assert_no_claude_writes`'s generalized `allowed_paths` argument, so adding a class means adding a manifest row, not a code branch. Because that file is the `.claude/` write allowlist, it is owner-reviewed through CODEOWNERS from B1 on.

Conformance: each of B1 through B5 ships positive, negative, and edge tests for its compile module (render byte-identical to a fixture; missing partial or malformed template exits with a configuration error; an untemplated file in the class is left untouched; a NO-REGEN-sentineled file is skipped and reported; a symlinked install directory or file, or one that resolves outside the repository root, exits with a configuration error), mirroring the conformance shape ADR-108 section "Implementation Notes" already established for skills, with the symlink and containment cases added because `skill_templates.py`'s checks do not cover sibling classes.

Rollback: revert B6, then B5 through B1 in reverse, then move this record to `rejected`. After each revert, run `build_all.py` at that commit and `build_all.py --check`; a green check is the proof that the four trees again match the templates byte for byte, which a bare PR revert does not establish when template-only commits landed in between. Reverting B6 fixes future installs only: a consumer who updated `project-toolkit` from `./src/claude` during the window keeps that copy until their next update, so B6 is a one-way door for that window, which is why it is last.
