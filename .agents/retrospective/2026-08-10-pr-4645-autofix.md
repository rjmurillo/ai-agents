# PR 4645 Autofix Repair Retrospective

## What happened

PR 4645 (fix/fail-open-audit) sat with two red required checks and armed
auto-merge. Both failures came from the branch aging, not from the code under
review.

`Run Python Tests` failed at the whole-tree ruff count ratchet:

```text
ruff count ratchet: BASELINE ABOVE BASE. This tree records 43,
FETCH_HEAD records 30 (+13). The measured count is 27, which FETCH_HEAD
already allows, so nothing in this tree added violations.
```

The branch carried `scripts/ci/ruff_count_baseline.txt` at 43 from its
merge base. `main` had since lowered the ceiling to 30. The ratchet is
one-directional, so the stale higher baseline read as an attempt to raise it,
even though the tree measured 27 and added nothing.

`Validate PR` failed on two separate steps:

1. Description validation reported a file claimed but absent from the diff.
   The description named four scripts. Two of them,
   `scripts/ci/spec_extract_refs.py` and `scripts/ci/spec_load_content.py`,
   had already landed on `main` in `4627d8482944dccad8e92e36f32dd9105ceec7ab`
   for Issue #4068. A later merge from `main` into this branch collapsed those
   hunks to nothing, so the diff shrank from four code files to two while the
   description stayed as written.
2. `scripts/ci/check_pr_qa_report.py` found no QA report for a PR with code
   changes and exited 1. The session log also lacked the required
   `sessionEnd.qaValidation` item.

## Failure mode classification

Pattern 4, false completion markers
(`.agents/governance/FAILURE-MODES.md`). The PR description asserted work
that the diff no longer contained. The assertion was true when written and
became false when `main` absorbed the same fix through another PR. Nothing
re-checked it.

## Evidence

- Failing run for `Run Python Tests`:

- Failing run for `Validate PR`:
  <https://github.com/rjmurillo/ai-agents/actions/runs/31378098190/job/93421830020>
- Superseding commit on `main`: `4627d8482944dccad8e92e36f32dd9105ceec7ab`,
  "fix(ci): preserve extracted failure semantics", Issue #4068.
- Proof of supersession: `git diff origin/main origin/fix/fail-open-audit --
  scripts/ci/spec_extract_refs.py scripts/ci/spec_load_content.py` printed
  nothing.
- After the base refresh: `ruff count ratchet: OK. 27 violations <= baseline
  30 (-3 slack).`

## Root cause

The branch's diff is defined against a moving base, but the PR description and
the ratchet baselines were both captured once against a fixed base. Neither
has a mechanism that re-evaluates on base movement. A long-lived branch
therefore accumulates two silent staleness classes: description claims that
the base has since absorbed, and ratchet files whose values the base has since
tightened. Both surface only as a red check, and the check names the symptom
rather than the age.

## Remediation

- Refreshed the base with a merge from `origin/main`, taking `main`'s baseline
  of 30. Verified by re-running the ratchet locally.
- Rewrote the PR description to name only the two files still in the diff, and
  recorded where the other two landed.
- Added `.agents/qa/pr-4645-fail-open-gates-report.md` bound to the base
  refresh commit, and the missing `sessionEnd.qaValidation` item in
  `.agents/sessions/2026-08-04-session-9102-fail-open-audit.json`.

## Lesson

When a required check fails on a branch older than a few days, compare the
branch against current `main` before reading the failure as a defect in the
change. Two of the three failures here were age, not code. The description
check is worth running against the live diff at every base refresh, since a
merge that resolves cleanly can still invalidate a sentence in the PR body.
