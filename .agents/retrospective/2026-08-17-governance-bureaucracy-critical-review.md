# Retrospective: Critical Review of Open Issues, PR Backlog, and Governance Overhead

## Session Info

- **Date**: 2026-08-17
- **Trigger**: Owner-requested critical review of the entire open-issue and PR backlog, motivated by concern that self-referential governance/CI machinery is generating more maintenance cost than value, and that customers installing this repo's plugin inherit that same overhead.
- **Scope**: 92 open issues, 11 open PRs, session-log/ADR/rule-file volume, one live CI-gate defect found while shipping the first fix.

## Failure mode classification

Per `.agents/governance/FAILURE-MODES.md`, this retrospective's most concrete, evidenced instance is **FM #9, Confident-Incorrectness Recurrence**: during the SESSION-PROTOCOL.md tier-hierarchy cut (see Decisions made, and the session log's `workLog` entries), the replacement text asserted ADR-009's escalation target as "orchestrator" without quoting the canonical source. ADR-009:81/:91 actually names `high-level-advisor`. This is the exact partial-signal-to-confident-delivery shape FM #9 describes, caught here by an independent `critic` agent review before the change reached a gate, not after.

The three live gate defects found in this session (`check_sessions()` missing `--existing-log`; `retrospective-policy`'s `{push_files}` empty-on-first-push; `validate_qa_skip_scope`'s unconditional rejection of `SKIPPED: docs-only`) do not cleanly fit any of the eleven cataloged patterns: each is a validator over-enforcing (blocking work a documented exception should have allowed) rather than under-enforcing (a silent pass, FM #10's shape) or a false completion claim (FM #4). No new class is proposed here; flagging the gap rather than forcing a fit per this rule's own evidence standard.

## What was measured

A three-way parallel audit (issue taxonomy, PR churn, bureaucracy-cost) against real GitHub state, not assumptions:

- **87 of 92 open issues (94%)** are the repo's own governance/CI/validation machinery breaking itself, not product-facing skill/agent work. Ten root-cause clusters explain 40 of the 92 numbers (worktree isolation alone spans 7 issues: #4498, #4698, #4702, #4917, #5061, #5111, #5123).
- **Six issues are genuinely urgent**, verified by reading the issue bodies directly rather than trusting titles: #5111 (P0, sessions creating worktrees under `/tmp` filled a 16G tmpfs and halted all work once already), #5090 (`core.hooksPath` pointed at a nonexistent directory, silently disabling all 24 pre-push jobs repo-wide, a *repeat* of a fix already applied once on 2026-07-19), #5099 (CVSS 8.8: the `/ship` completion gate verifies its config file's byte-identity but never checks the verifier scripts the config dispatches, so a PR can rewrite a verifier and still get a trusted `all_passed:true` verdict), #4607 (CI shares one GitHub rate-limit budget with every interactive agent session because `BOT_PAT` authenticates as the human account), plus #5102 and #2993 which directly block pushes today per their own titles.
- **Nine issues were confirmed safe to deprioritize** (narrow blast radius, no live-incident evidence, or pure process/documentation alignment with no named functional defect): #5117, #5118, #5115, #5121, #5070, #5043, #4962, #5068, #5014. Closed with evidence-linked comments; reopen is one click if any recur.
- **PR spin-out confirmed, in two distinct failure modes.** Mode 1 (review-driven spin): PR #4846 has 235 commits against 16 changed files, still fails its own security scan, self-admits via `commit-limit-bypass`/`infrastructure-failure` labels: flagged to the owner recommending close-and-restart rather than acted on unilaterally, since it predates this session. PR #5036 has the same root-cause bug (an unanchored `^serena-` regex that silently never fires) reported 4 separate times across 14 open threads; handed the exact fix to the PR instead of re-deriving it. Mode 2 (process-ritual spin, a genuinely new finding): PRs #5103/#5107 show 18-19 commits with **zero** open review threads: the commit count is inflated entirely by the QA/session-evidence rebind mechanism firing on every `main` merge into a long-lived branch, not by review disagreement.
- **The owner's claim "session log is git history with extra steps" is directionally right, sharper than stated.** `git ls-tree -r --name-only origin/main -- .agents/sessions` at time of writing counts 1,499 session-log files: 62 (4%) are legacy narrative `.md` files (abandoned since roughly Jan-Jun 2026), and 1,437 (96%) are the current JSON worklog format. Sampling found their bodies are ~65-70% boilerplate protocol-compliance checkboxes restating rules that already exist in `AGENTS.md`/`session-logs.md`, carrying zero session-specific information. A live PR (#5092) shipped 5 of its 16 commits purely to rebind `endingCommit` and regenerate the episode record: the session-log mechanism is now injecting pure administrivia *into* git history, not just duplicating what's already there.
- **Rule-file audit** (14 of 27 files sampled) found three concrete, evidenced overlaps safe to consolidate without losing binding force: a DRY/testing/error-handling triplication across `code-quality.md`, `pragmatic-programmer.md`, `unified-software-engineering.md` (~690 combined lines loading together on every code edit); a partially-deduplicated "Boil the Lake"/"User Sovereignty" restatement between `builder-ethos.md` and `voice.md` (both in the always-on 70KB/turn set); and a fully-restated "self-referential test" anti-pattern paragraph in both `generated-artifacts.md` and `canonical-source-mirror.md`.
- **ADR audit** (10 of 96 sampled across the full range) found 8 of 10 were process/governance ceremony (linter config, a `.gitattributes` line-ending entry, a CI-workflow step placement, an agent rename its own text calls "one git revert reversible") that still received the full 6-agent `adr-review` debate apparatus reserved, in principle, for genuinely hard-to-reverse decisions like the 2 real architecture ADRs sampled (ADR-007 memory architecture, ADR-042 language migration).

## Decisions made

1. **Closed 9 confirmed-deprioritizable issues** with evidence-linked comments rather than leaving them to accumulate in the backlog count silently. Chose "comment + close" over silent triage so the reasoning is auditable and reversible.
2. **Did not unilaterally close or rewrite PR #4846 or #4954.** Both predate this session and represent substantial prior work by the repo owner; flagged with full evidence and a specific recommendation instead, deferring the actual decision.
3. **Fixed the smallest, highest-confidence, lowest-risk item first** (the `generated-artifacts.md` / `canonical-source-mirror.md` duplication) rather than attempting the larger always-on-rule-file trims or the `SESSION-PROTOCOL.md` rewrite in the same pass, because those touch a test that pins exact byte counts for the always-on rule corpus (`tests/validation/test_always_on_corpus_claims.py`) and, for the session protocol, the enforcement scripts themselves (`git_hook_policy.py`, `validate_session_json.py`), and both need a dedicated, careful pass rather than being bundled into a first quick win.
4. **Found a live gate defect while shipping the first fix**: the `retrospective-policy` pre-push hook's `{push_files}` lefthook template resolves empty on a brand-new branch's first push (no prior remote ref to diff against), which defeats the hook's own documentation-only bypass (`_documentation_only` never runs against an empty path list) and forces retrospective evidence even for a pure 3-file markdown change. Did not bypass via `SKIP_RETROSPECTIVE_GATE=true` (forbidden by this repo's own rules); wrote this retrospective instead, which is genuinely load-bearing content, not just gate-satisfying ceremony.
