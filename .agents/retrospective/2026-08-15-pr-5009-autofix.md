## Phase 1: Insights Generated

### Five Whys: Repeated Push Failures

**Problem:** The session validated and recorded a PASS QA report at 04:15Z
against commit b485b6385173b9a5f298e624b6aa42dfb0233b42, then at 06:20Z found
the remote head of feat/dx-review had changed outside the session, forcing a
full replay of the verified fixes onto the new base (410ad9acd) before a push
could succeed.

**Q1:** Why did the push attempt fail against the original base?
**A1:** The remote branch tip had advanced past the commit the session had
validated; the local verified work was no longer a fast-forward of the
current remote head.

**Q2:** Why did the remote head advance while this session held work in
progress?
**A2:** Another actor pushed commits to feat/dx-review during the same
window (the branch log shows a sequence of dx-review docs/session/skill
commits, including 410ad9acd, landing between this session's triage and its
first validation pass). PR autofix operates on a shared branch under lease
discipline, and a lease renewal does not block every external write path.

**Q3:** Why wasn't the divergence caught before the first push attempt?
**A3:** The session validated fixes against the branch state captured at
triage (starting commit d0491fbf8) and did not re-read the live remote head
immediately before pushing; it re-checked only after the push failed.

**Q4:** Why does this gap recur despite existing guidance?
**A4:** The live-state discipline that requires re-reading head SHA, base
SHA, checks, and threads after each main advance is documented as operator
practice in `.serena/memories/pr-autofix/fleet-operations.md` and
`.serena/memories/pr-autofix/pr-4323-late-base-refresh.md`, not enforced by
an automated gate. A session under token or time pressure can still validate
against a captured-earlier SHA and only discover the drift when the push
itself rejects.

**Q5:** Why is there no mechanical enforcement of this check?
**A5:** No committed pre-push script currently fails closed when the parent
SHA of the commits about to be pushed does not match the current remote head
of the target branch; the safeguard lives in memory-recorded operator
discipline (also traced to issue #4349 in `pr-4323-late-base-refresh.md`),
not in a hook.

**Root Cause:** Verified fixes were checked against a captured, aging branch
snapshot instead of the live remote head, and no automated gate blocks a push
whose parent does not match that live head.

**Actionable Fix:** This session's recovery already applied the existing
pr-autofix practice correctly: it discarded the stale base, rebuilt the
verified net fixes on the new remote head (410ad9acd), and prepared a compact
fast-forward branch. The push remains pending this retrospective evidence.
That practice is pre-existing (ADR-076 alignment, fleet-operations.md,
pr-4323-late-base-refresh.md); this session is additional evidence that it
works, not a new finding. Automated pre-push enforcement of the live-head
check remains an open gap outside this session's scope.

### Fishbone Analysis

Not run. The repeated push failure traces to a single root cause (stale-base
validation, Five Whys above), not a multi-category failure needing
cross-category correlation.

### Learning Matrix

#### Continue (What worked)
- Rebuilding verified fixes on the new remote head and pushing only a
  fast-forward commit when the branch moved underneath the session.
- Stress-testing race-prone tests in 30 consecutive fresh pytest processes
  before declaring a concurrency fix stable.
- Measuring exact resource behavior (workers, rule timeout, wall-clock time)
  before picking Semgrep scan parameters, instead of guessing a lower bound.

#### Change (What didn't work)
- Validating fixes against a branch snapshot captured at triage time, then
  discovering divergence only when the push itself rejected.

#### New approaches
- Isolating a security command-contract assertion into a small dedicated
  test file to shrink the file set a full-repo scan has to cover, without
  reducing what the contract itself checks.

#### Invest
- An automated pre-push check that fails closed when the parent SHA of the
  commits being pushed does not match the current remote head, replacing
  operator memory discipline with a mechanical gate.
