# Seam tables

Detail behind Phase 1 of the skill. Ask `generator_inventory.py path <repo-path>` first. Use these tables for the reasons.

## Tree roles

| Tree | Role | Canonical source | Regenerated by |
|------|------|------------------|----------------|
| `templates/agents/*.shared.md` | canonical for agents | itself | n/a |
| `src/vs-code-agents/`, `src/copilot-cli/agents/` | generated | `templates/agents` | `build/generate_agents.py` |
| `docs/agent-catalog.md` | generated | `templates/agents` | `build_all.py` (agent-catalog) |
| `templates/skills/*.SKILL.md.tmpl` | canonical for every skill's SKILL.md (ADR-108, ADR-109 B3) | itself | renders `src/claude/skills/`, links `.claude/skills/<name>`, mirrors `src/copilot-cli/skills/` |
| `src/copilot-cli/{skills,instructions,hooks}` | generated | `.claude/` trees | `build_all.py` |
| `.github/instructions/` | generated | `.claude/rules/` | `build_all.py` (rules) |
| `scripts/{hook_utilities,github_core,ai_review_common}` | canonical for shared Python | itself | n/a |
| `src/claude/lib/`, `src/copilot-cli/lib/` | generated | `scripts/` packages | `build_all.py` lib step (B5) |
| `.claude/lib/` | link into `src/claude/lib/` | `src/claude/lib/` | `build_all.py` binplace |
| `src/claude/{agents,rules,hooks,hooks.json,settings.json}` | generated (ADR-109 B1, B2, B4) | `templates/{agents,rules,hooks}/` | `build_all.py`, then binplaced to `.claude/` |
| `src/claude/AGENTS.md`, `src/claude/claude-instructions.template.md` | hand-maintained, no template | itself | n/a |

A shipped skill renders `src/claude/skills/<name>/SKILL.md` first. `.claude/skills/<name>` links to that directory (ADR-119). The Copilot copy step mirrors it, plus the skill's hand-maintained `scripts/`, `references/`, and `tests/`, into `src/copilot-cli/skills/<name>/`. A repo-local skill (`metadata.distribution: repo-local`) renders only to `.claude/skills/<name>/`, and its support files are hand-maintained there.

## Generator order

Run `generator_inventory.py generators` for the list and order. Order is load-bearing (the `Order matters` comment above `GENERATORS`). What each reads and writes:

| Generator | Reads | Writes |
|-----------|-------|--------|
| agents | `templates/agents/*.shared.md`, `templates/platforms/*.yaml` | `src/copilot-cli/agents/`, `src/vs-code-agents/` |
| agent-catalog | `templates/agents/*.shared.md` | `docs/agent-catalog.md` |

| lib | `scripts/` packages | `src/claude/lib/`, `src/copilot-cli/lib/`, binplaced `.claude/lib/` |
| skills | template-owned skills compile first | `src/copilot-cli/skills/` |
| rules | `.claude/rules/*.md` | `.github/instructions/`, `src/copilot-cli/instructions/` |
| hooks | `.claude/settings.json`, `.claude/hooks/` | `src/copilot-cli/hooks/`, `hooks.json` |

## Facts that prevent confusion

- `build_all.py` forbids generator writes under `.claude/` (REQ-003-010) and exits 2 with `REQ-003-010 VIOLATION`. The exception is a `binplace.yaml` row's `.claude/`-rooted `install_tree`.
- `--check` flags staleness only inside `OWNED_PREFIXES`. Read the tuple with `generator_inventory.py generators`, not from memory; it changed after the earlier prose was written.
- The hooks generator maps Stop, SubagentStop, PermissionRequest, and PreCompact to their PascalCase compatibility names. Stop and SubagentStop stay direct host registrations because their structured decisions need host-level merging. A reported drop needs an identified source registration; never assume it is normal.
- Every run overwrites the generation audit log under the gitignored `build/audit/`. Read it to see what each generator did.
